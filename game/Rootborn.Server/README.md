# 데디케이티드 서버 돌리기

친구들과 같이 할 방을 집 PC나 늘 켜 두는 기계(예: 집의 Linux 기계)에 띄우는 사람을 위한 안내다.
서버는 화면이 없는 프로그램이고 방 하나를 연다. 게임을 하는 사람은 게임의 **서버 주소로 들어가기**로 들어온다.

아래에서 `<...>`는 자리 표시다. 실제 주소·포트·폴더는 자기 기계에 맞게 넣는다.

## 1. 서버 받기

저장소에서 배포 폴더를 만든다(`Tools/publish/README.md`):

```bash
bash Tools/publish/publish.sh --server linux-x64   # 또는 win-x64
```

`output/publish/server-<플랫폼>/` 폴더가 서버 전부다(실행 파일, 런타임, `data/`, `game/`, 집 맵). .NET을 따로 깔 필요가 없다.
이 폴더를 서버를 돌릴 기계 아무 곳에 복사한다. 폴더 안의 파일은 고치지 않는다(고치면 데이터가 달라져 아무도 못 들어온다 — 아래 9절).

## 2. 띄우기

필요한 값은 네 가지다: 세이브 폴더, 슬롯 이름, 들을 주소(이 기계의 LAN 주소), 포트.

Windows(PowerShell):

```powershell
cd <서버 폴더>
.\Rootborn.Server.exe --save-root <세이브 폴더> --slot <슬롯 이름> --bind <이 기계의 LAN 주소> --port <포트>
```

Linux:

```bash
cd <서버 폴더>
./Rootborn.Server --save-root <세이브 폴더> --slot <슬롯 이름> --bind <이 기계의 LAN 주소> --port <포트>
```

- 이 기계의 LAN 주소는 Windows는 `ipconfig`, Linux는 `ip addr`로 본다(보통 공유기가 준 주소).
- 포트는 1024~65535 중 다른 프로그램이 쓰지 않는 수를 고른다. `0`을 주면 빈 포트를 받아 로그의 `듣는 중: ` 줄에 찍는다(시험용).
- 슬롯이 없으면 새 방을 만들고(`새 방을 만듦`), 있으면 이어서 연다(`방을 이어서 엶`).
- 모든 값은 환경 변수로도 줄 수 있다(인자가 먼저). 전체 목록은 `--help`나 `game/README.md`의 "서버".

| 인자 | 하는 일 | 없을 때 |
|---|---|---|
| `--save-root`, `--slot`, `--bind`, `--port` | 위 네 가지 | 반드시 준다 |
| `--max-players <정원>` | 1~8 | 4. 방을 처음 만들 때만 정한다 |
| `--share <조각,...>` | 같이 쓸 것(3절) | `none`(시간만) |
| `--day-copies <N>` | 날마다 남기는 사본 수(6절) | 3 |
| `--autosave-seconds <초>` | 주기 저장 간격(6절) | 60, 0이면 끔 |
| `--log <파일>` | 로그를 파일에도 쓴다(8절) | 표준 출력만 |
| `--log-max-mb <MB>`, `--log-files <N>` | 로그 파일 하나의 한도, 돌려 쓴 지난 파일 수 | 10MB, 5개 |

끄기: 콘솔에 `stop`, 또는 Ctrl+C, 또는 종료 신호(서비스 끄기). 방 상태를 저장하고 들어와 있는 사람을 끊는다.

## 3. 같이 쓸 것 고르기

시간(날·시각)은 항상 같이 쓰고, 가방과 개인 성장은 항상 각자다. 그 밖에 `--share`로 고른다(쉼표로):

- `wallet` — 돈을 같이 쓴다
- `house` — 집과 가구와 집 꾸밈(벽지·바닥·띠 색, 조각 `house-build`는 `house`를 따라 켜진다)을 같이 쓴다
- `town` — 마을 상태를 같이 쓴다
- `none` — 시간만

예: `--share wallet,house`. **방을 처음 만들 때만 정한다.** 이미 있는 방에 다른 값을 주면 로그에 남기고 저장된 설정을 쓴다.
바꾸고 싶으면 새 슬롯으로 새 방을 만든다.

## 4. 친구가 들어오는 법

게임의 슬롯 선택 아래 **서버 주소로 들어가기** → 주소에 `<서버 주소>:<포트>`를 넣고, 들어갈 인물(그 PC의 이야기가 있는 슬롯)을 고른다.
같은 집(같은 공유기) 안이면 서버 기계의 LAN 주소를 쓴다. 그 사람의 진행은 서버의 `guests/` 아래에 남는다(6절). 같은 PC의 같은 인물로 다시 들어오면 이어진다.

## 5. 집 밖에서 들어오려면

집 밖의 친구는 공유기 바깥 주소로 들어와야 한다. 일반적으로 필요한 것:

1. 공유기 설정의 **포트 포워딩**에서 바깥의 UDP `<포트>`를 서버 기계의 `<LAN 주소>:<포트>`로 보낸다(공유기마다 메뉴 이름이 다르다).
2. 서버 기계의 방화벽에서 그 UDP 포트를 연다.
3. 친구는 공유기의 바깥 주소(공인 주소)와 그 포트로 들어온다. 바깥 주소는 바뀔 수 있다.

위험: 포트를 열면 인터넷의 누구나 그 포트에 닿을 수 있다. 방에는 아직 비밀번호가 없으므로, 같이 할 때만 열고 끝나면 닫는다.
바깥 주소를 공개된 곳에 올리지 않는다.

## 6. 세이브

```
<세이브 폴더>/<슬롯>/
  room-clock.json, room-settings.json, room-piece-*.json, ...   방의 시계·설정·같이 쓰는 것(집 꾸밈은 room-piece-house-build.json과 잡기 room-piece-house-build-holds.json)
  guests/<플레이어>/                                               들어온 사람마다 그 사람의 세이브
  backups/<날>/                                                    날마다 남긴 방 파일의 사본(최근 --day-copies 개)
  guests/<플레이어>/backups/<날>/                                  손님 세이브의 날 사본
  room-request-ledger.json                                        방이 답한 요청(같은 요청을 두 번 반영하지 않게)
  .room-lock, .room-lock-owner                                     잠금(7절) — 건드리지 않는다
```

언제 저장되는지와 서버가 갑자기 꺼졌을 때(정전, 강제 종료) 잃을 수 있는 것:

| 무엇 | 언제 쓰나 | 갑자기 꺼지면 잃는 것 |
|---|---|---|
| 방의 시계(날·시각) | 들어옴·나감·잠·날 바뀜·게임 1시간마다, 주기 저장, `save`, 끌 때 | 마지막으로 쓴 뒤의 시간(기본 데이터로 게임 1시간 = 실제 25초, 주기 저장 기본 60초) — 다시 켜면 그때 시각부터 |
| 같이 쓰는 것(돈·집·마을)과 요청 장부 | 요청을 반영할 때마다(한 묶음으로), 주기 저장, `save`, 끌 때 | 없음 |
| 손님의 진행 | 손님 게임이 저장할 때마다 받아 쓴다(검사를 지난 것만) | 그 손님이 아직 보내지 않은 것(손님 쪽 게임의 저장 시점) |
| 날 사본 | 방의 날이 바뀔 때 | 없음(전날 것까지 있다) |

- 파일은 임시 파일에 쓰고 바꿔치기한다. 쓰는 도중 꺼져도 반쯤 쓴 파일이 남지 않는다.
- 손님 세이브를 받아 쓴 뒤 같이 쓰는 것을 쓰기 전에 꺼지면, 그 손님이 다시 들어올 때 남은 요청을 반영한다(한 번만).

**사본에서 되살리기**: 서버를 끄고, `<슬롯>/backups/<날>/` 안의 파일을 `<슬롯>/`에 덮어 복사한다(손님은 `guests/<플레이어>/backups/<날>/` →
`guests/<플레이어>/`). 되살리기 전에 슬롯 폴더 전체를 따로 복사해 두면 되돌릴 수 있다.

## 7. 같은 세이브를 두 번 열지 않는다

같은 세이브 폴더·슬롯을 서버 둘이, 또는 서버와 게임의 "내 PC에서 방 열기"가 함께 열면 두 번째는 시작하지 않는다(끝 코드 6).
로그에 이미 연 쪽(프로세스 번호, 기계, 시작 시각)이 나온다. 그쪽을 끄거나 다른 슬롯을 쓴다.
서버가 정상으로 끝나지 못하고 꺼졌어도 잠금은 운영체제가 풀어 주므로 그냥 다시 켜면 된다(`지난번에 끝내지 못하고 꺼진 서버의 잠금을 넘어감`).

## 8. 콘솔 명령과 로그

서버 창(콘솔)에 한 줄씩 넣는다. `help`가 목록을 보인다.

| 명령 | 하는 일 |
|---|---|
| `status` | 방의 날·시각, 정원, 같이 쓰는 것, 들어와 있는 사람(이름·신원), 가동 시간, 마지막 저장 시각 |
| `players` | 들어와 있는 사람 |
| `save` | 지금 저장한다 |
| `help` | 명령 목록 |
| `stop` | 저장하고 끈다 |

모르는 명령은 `help`를 가리킨다. 서비스로 돌아 콘솔이 없으면 명령을 받지 않는다(그래도 서버는 계속 돈다).

로그는 줄마다 시각(`2026-11-12 21:05:09`)이 붙는다. 남는 것: 방 열기, 듣는 주소, 들어옴·나감, 버전이 달라 접속 거절(이유), 손님 저장을 받지 않음(이유),
날이 바뀜, 사본 남김, 저장함(주기·명령), 오류, 끝냄. `--log <파일>`을 주면 같은 줄이 파일에도 남고, 파일이 `--log-max-mb`에 닿기 전에
`<파일>.1`, `.2` …로 밀어 `--log-files`개만 둔다(기본으로 많아야 60MB). 들어온 사람의 접속 주소는 로그에 남지 않는다(접속은 번호로만 보인다).
정원이 차서 거절한 접속은 아직 로그에 남지 않는다.

## 9. 자주 나는 오류

| 끝 코드 | 로그 | 고칠 것 |
|---|---|---|
| 2 | 빠진 값·모르는 인자 | 도움말대로 인자를 준다 |
| 3 | 데이터 오류 | 배포 폴더가 깨졌다. 다시 받는다 |
| 4 | 세이브를 읽을 수 없다 | 세이브 파일이 깨졌거나 더 새 버전이 만든 방이다. 덮어쓰지 않았으니 사본에서 되살리거나(6절) 새 버전 서버를 쓴다 |
| 5 | 포트를 다른 프로그램이 이미 쓰고 있다 | 그 프로그램(다른 서버 포함)을 끄거나 다른 `--port` |
| 5 | 이 기계의 주소가 아니다 | `--bind`에 이 기계의 LAN 주소(`ipconfig`/`ip addr`) |
| 6 | 이 슬롯은 이미 다른 곳에서 열려 있다 | 7절 |
| 7 | 세이브 폴더에 쓸 수 없다 / 로그 파일을 열 수 없다 | 폴더 권한과 남은 공간, 또는 다른 `--save-root`·`--log` |
| 8 | 도는 중에 멈췄다 | 저장은 해 보고 끝냈다. 로그를 남겨 알린다 |

**버전이 다르면 못 들어온다.** 서버와 게임이 같은 커밋에서 만든 것이고 데이터가 같아야 한다. 로그의 방 열기 줄에 `game 1.0.0+<커밋>`과 `data <지문>`이 있고,
다르면 들어오려는 쪽에 "서버와 게임 버전이 달라요" 또는 "데이터가 달라요"가 뜬다(서버 로그에는 `접속 거절 ...: game version mismatch` 등).
데이터 지문에는 짓는 집의 LDtk 파일이 든다(`game/world/maps.json`에서 `build`가 있는 맵). 집 맵을 다시 만든 판과 옛 서버는 서로 "데이터가 달라요"로 못 들어온다.
게임을 새로 받으면 서버도 같은 것으로 바꾼다 — 세이브 폴더는 그대로 쓰면 된다.

## 10. 서버를 옮기기

1. 옛 기계에서 `stop`으로 끈다(저장).
2. `<세이브 폴더>/<슬롯>/` 폴더를 통째로 새 기계에 복사한다(잠금 파일이 같이 가도 된다).
3. 새 기계에 같은 버전의 배포 폴더를 두고 같은 `--slot`, 새 기계의 `--bind`로 띄운다. 친구에게 새 주소를 알린다.

## 11. Linux에서 계속 켜 두기 (systemd 사용자 서비스)

관리자 권한 없이 자기 계정의 서비스로 돌린다. 예시 파일: `game/Rootborn.Server/rootborn-server.service.example`.

```bash
mkdir -p ~/.config/systemd/user
cp rootborn-server.service.example ~/.config/systemd/user/rootborn-server.service
# 파일 안의 <...> 자리를 자기 값으로 바꾼다
systemctl --user daemon-reload
systemctl --user enable --now rootborn-server
systemctl --user status rootborn-server
journalctl --user -u rootborn-server -f      # 로그 보기
systemctl --user stop rootborn-server        # 끄기(종료 신호 → 저장하고 끝)
```

로그인하지 않아도 켜져 있게 하려면 `loginctl enable-linger <사용자>`가 필요하다. 이것은 기계 설정에 따라 관리자에게 부탁해야 할 수 있다.
서비스로 돌면 콘솔 명령을 넣을 수 없다 — 상태는 로그(`--log` 파일이나 `journalctl`)로 본다.
