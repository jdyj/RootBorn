# 엔진 무관 게임 규칙과 실제 플레이 근거

Claude와 Codex 모두 따른다. 2026-11-07 사용자 결정. MonoGame 판 기준으로 고쳐 씀.

## 1. 게임 규칙은 엔진과 무관한 Core에 있다

- 진행도, 조건 판정, 보상 계산, 일정, 퀘스트·업적 평가, 세이브 모양, 월드 판정(걷기·충돌·문·상호작용 범위)은 `Rootborn.Core`(`Packages/com.rootborn.core/Runtime`)에 있다. 엔진·파일·JSON 라이브러리를 참조하지 않는다(CI가 막는다).
- 규칙 단위 테스트는 `dotnet test Tools/Rootborn.Core.Tests`로 엔진 없이 몇 초에 돈다. 같은 동작을 다른 층에서 중복 검증하지 않는다.
- 새 규칙도 Core에 쓴다. 화면·Host에 규칙 판단을 쓰지 않는다. 자세한 제약은 `rules/coding-standards.md`.

## 2. "확인했다"는 실제 입력으로 확인한 것만 쓴다

### 왜

내부 함수 호출, 상태 강제 설정, 입력칸에 값 직접 넣기로 확인한 것을 실제 플레이로 확인한 것처럼 보고한 일이 반복됐다. 사용자는 이것을 플레이하지 않고 한 척한 것으로 받아들였다.

### 근거의 종류

| 종류 | 무엇 | 보고에 쓰는 이름 |
|---|---|---|
| 자동 테스트 | Core·Data·World·Game·Ui·Screens 테스트. 규칙, 데이터, 칸 단위 걷기, `GameSession` 명령으로 진행, 창 없이 화면 누르기 | "자동 테스트" — 화면에 보인다는 근거로 쓰지 않는다 |
| 장치 이벤트 주입 | `Rootborn.Host.Tests`: 실제 창과 게임 루프를 한 프레임씩 돌리며 키·글자는 SDL 이벤트 큐에, 포인터는 게임의 포인터 장치 계층에 넣는다. 클릭은 UI 포인터 판정을 거친다 | "장치 이벤트 주입, OS 입력 계층 미확인" |
| OS 입력 | FEVM의 Xvfb + xdotool, Windows VM, 또는 사람이 실제 키보드·마우스로 | "실제 입력(OS)" |
| 직접 본 화면 | 그려진 화면 버퍼에서 저장한 스크린샷을 보고 전에 직접 열어 본 것 | 스크린샷 경로 |

### 보고 규칙

- "확인한 것"에는 장치 이벤트 주입, OS 입력, 직접 본 화면으로 확인한 항목만 쓰고 종류를 붙인다. 항목마다 근거(테스트 이름 또는 스크린샷 경로)를 붙인다.
- 다음으로 확인한 것은 "실제 플레이로는 미확인"에 따로 적고 무엇을 건너뛰었는지 쓴다: `GameSession` 명령 직접 호출, 순간이동이나 자리 강제 지정, 상태 강제 설정, 날짜·시각 강제 변경, 필드나 입력칸에 값 직접 넣기, 버튼 동작 직접 실행.
- 자동 테스트 통과와 데이터 확인은 "자동 테스트"로 따로 적는다.
- 사람이 직접 해 본 플레이와 조작감은 사용자만 확인할 수 있다. 그 전에는 "실제 플레이로 확인"이라고 쓰지 않는다.
- 테스트가 사용자의 마우스·키보드를 OS 수준으로 조작하지 않는다.
