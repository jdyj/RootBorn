# 엔진 이전 기간 규칙 (Unity → MonoGame)

2026-11-11 사용자 결정. Claude와 Codex 모두 따른다. 전체 방향은 `docs/superpowers/specs/2026-11-11-unity-removal-design.md`, 규칙 떼어내기는 `docs/superpowers/specs/2026-11-11-core-rules-extraction-design.md`.

## 지금 상태

- **Unity 판은 저장소에서 지웠다(2026-11-12).** 태그 `unity-playable-20261111`이 플레이 가능한 기준본이고, Unity 코드와 옛 에셋은 그 태그에서 읽는다(`git show unity-playable-20261111:<경로>`). `Assets/`에는 게임이 읽는 그림과 LDtk 맵만 남아 있다(Unity 시절 폴더 이름이다).
- **끝난 것**: 규칙 옮기기(Core, `NotPortedYet` 비어 있음), 정의 로더·세이브 저장소(데이터는 `data/`가 원본, 변환기는 지웠다), 월드(LDtk 직접 읽기, 걷기·문·상호작용, 세이브 슬롯), 화면 옮기기(메인 체인을 MonoGame 판에서 처음부터 끝까지 — Host `MainChainHostTests`, 장치 이벤트 주입), Unity 제거(Core를 `game/Rootborn.Core`로 옮김, 2026-11-12). CI는 dotnet 기준(`Scripts/ci`).
- **남은 것**: Steam(조사 `docs/superpowers/specs/2026-11-12-steam-research.md`)과 멀티플레이의 남은 단계(`2026-11-12-multiplayer-design.md`). 아직 없는 것의 규칙은 미리 쓰지 않는다.
- 새 기능을 넣을지는 사용자가 정한다. 사용자가 정해 더한 것: 흐르는 시간(`2026-11-12-flowing-time-design.md`), 멀티플레이의 공유 설정과 서버, 단축키 안내.
- 데이터의 원본:
  - 규칙 데이터는 `data/`가 원본이고 손으로 고친다(`data/README.md`). 엔티티의 `asset` 필드는 옛 Unity 경로를 적어 둔 것이고 새 엔티티에는 쓰지 않아도 된다. 균형 수치를 고친 기록은 `docs/superpowers/specs/2026-11-12-time-balance.md`.
  - MonoGame 판이 직접 갖는 데이터: 덧붙인 문구 `game/localization`, 맵 목록·상호작용 지점 `game/world/*.json`, UI 테마 `game/themes`. 이것들은 손으로 고친다.
  - 맵은 LDtk 파일이 원본이다(지금은 `Assets/LDtk/` 아래, `game/world/README.md`). 새 그림과 맵은 `Assets/`가 아닌 새 자리에서 시작한다.

## 어디에 무엇을 쓰는가

- 게임 규칙: `game/Rootborn.Core`(`Rootborn.Core`). 엔진 참조 없음. 값은 생성자로 받고 엔티티는 id 문자열로 가리킨다. 엔티티 id로 분기하지 않는다.
- MonoGame 판: `game/`. MonoGame 참조는 실행 프로그램(Host)에만 둔다.
- 옮기면서 고칠 것은 고친다(아래 "고칠 것은 고치고 확장하기 쉽게").

## 고칠 것은 고치고 확장하기 쉽게

사용자 지시(2026-11-11): "진행하는데 개선할건 개선하고 확장성있게 할 수 있도록 해". Unity 코드를 그대로 베끼는 것이 목표가 아니다.

- **구조는 자유롭게 고친다.** 전역 상태·정적 호출을 없애고, 책임이 섞인 큰 클래스를 나누고, 이름을 바로잡는다.
- **확장하기 쉽게 만든다.** 새 엔티티는 데이터만 더하면 되고, 새 전략 종류는 클래스 하나와 등록 한 줄이면 되어야 한다. 종류를 enum이나 switch로 닫아 두지 않는다. 세이브 데이터에는 형식 버전을 두어 나중에 바꿀 수 있게 한다.
- **분명한 버그는 고친다.** 원본의 버그, 빠진 검사(부분 지급, 중복 적용, 음수 허용 등), 알려진 미수정 위험을 옮기면서 고친다.
- **고친 것은 숨기지 않는다.** Unity 판과 동작이 달라지는 곳은 테스트로 새 동작을 고정하고, 커밋 메시지와 `docs/superpowers/specs/2026-11-11-core-rules-extraction-design.md`의 "Unity 판과 달라진 동작" 목록에 한 줄씩 적는다.
- **게임 기획은 바꾸지 않는다.** 수치, 콘텐츠, 진행 순서, 화면 구성처럼 플레이가 달라지는 결정은 사용자에게 묻는다. 기존 세이브 파일은 계속 읽혀야 한다.
- 쓰이지 않는 확장점을 미리 만들지 않는다. 지금 있는 종류들이 깔끔하게 들어가는 구조면 된다.

## 테스트

- 규칙은 `dotnet test game/tests/Rootborn.Core.Tests`.
- dotnet 통과는 "자동 테스트"다. "실제 플레이로 확인"은 MonoGame 판의 장치 입력 테스트나 직접 본 화면에만 쓴다.

## 동시에 진행할 때

- 작업 폴더(worktree) 하나에 쓰는 세션 하나. 세션마다 자기 브랜치에 커밋하고 푸시하지 않는다.
- 자기 범위 밖 폴더를 고치지 않는다. main에 합치는 일은 조정 담당 세션이 한다.

## 되풀이하는 절차는 스킬로

사용자 지시(2026-11-11): 진행하면서 스킬로 만들 수 있는 것은 스킬로 만들어 Claude와 Codex 양쪽에 저장한다. 같은 내용을 `.claude/skills/<이름>/SKILL.md`와 `.agents/skills/<이름>/SKILL.md`에 둔다. 절차가 바뀌면 양쪽을 함께 고치고, 그 절차가 더 쓰이지 않게 되면 양쪽에서 지운다.

지금 있는 것: `parallel-claude-session`(세션 나눠 맡기고 합치기), `host-play-test`(MonoGame 판 화면 테스트), `ui-nine-slice-skin`(UI 그림을 재서 9조각 테마 스킨으로), `save-compat-change`(세이브에 닿는 것을 고칠 때 하위호환·상위호환), `balance-sim-run`(수치 균형 시뮬레이터를 고치고 원격에서 돌려 표를 견주기), `pixel-kit`(건물·타일·가구 그림을 부품과 규칙으로 그리기), `pixel-kit-room`(칸마다 벽/바닥만 정해 벽 그림과 충돌이 함께 든 LDtk 방 만들기).

## 그림은 갈아 끼울 수 있게

사용자 지시(2026-11-12): UI부터 실내 소품, 인테리어까지 그림을 전부 새로 만들 계획이다. 그림을 쉽게 바꿀 수 있게 만든다.

- **코드는 그림 파일을 모른다.** 화면은 스킨 이름과 아이콘 키만 말한다. 어느 PNG의 어느 칸인지, 테두리 두께, 글자 색은 테마·좌표표 데이터에 둔다. 그림을 바꾸는 일은 PNG와 그 데이터 파일을 바꾸는 일이어야 한다.
- **규칙과 그림을 나눈다.** 가구가 차지하는 칸, 막는지, 놓을 수 있는 면은 규칙이고 Core에 있다. 가구 그림을 바꿔도 규칙, 세이브, id는 그대로여야 한다. 캐릭터 부위와 맵 타일도 같다.
- **테스트는 특정 그림의 픽셀에 기대지 않는다.** 화면 테스트는 구성과 동작(무엇이 어디에 몇 개, 누르면 무엇이 바뀌는지)을 본다. 그림이 바뀌면 깨지는 테스트를 만들지 않는다.
- **지금 그림에 맞추는 데 시간을 쓰지 않는다.** Unity 판 화면과 그림을 맞춰 보는 일, 지금 그림의 어긋남을 고치는 일을 하지 않는다. 스크린샷은 결함(겹친 글자, 잘린 패널, 빈 그림)을 찾는 데만 쓴다.
- **화면 배치 수치는 화면마다 한 곳에 모은다.** 새 디자인에서 패널 크기와 위치가 바뀌어도 그 한 곳만 고치면 되게 한다. 패널 안 여백은 테마의 테두리 두께에서 얻는다.
- 그림 모양에 관한 선택(어느 타일, 어느 색)은 지금 원본대로 둔다.
- **맵도 새로 그린다(사용자 결정 2026-11-12).** 지금 맵의 어긋남(문이 그림보다 한 줄 아래, 닿을 수 없는 문, LDtk에 없는 구역)을 LDtk에서 고치지 않는다. 메인 체인을 걸어서 확인하는 데 필요한 길은 맵 데이터(`game/world/maps.json`, `interactions.json`)에 임시 연결로 두고 임시라고 적는다. 맵을 바꾸는 일은 LDtk 파일과 맵 데이터를 바꾸는 일이어야 하고, 코드가 특정 맵의 크기·좌표·이름에 기대지 않는다. 새 맵이 지켜야 할 약속(층 이름, 충돌 층, 문, 상호작용 지점)은 `game/world/README.md`에 적는다.

## 끝난 것은 남기지 않는다

Unity 관련 부분(영역, 도구, 절차)이 더 쓰이지 않게 되면 그때 해당 규칙 조항, 문서, 스킬·에이전트, 메모리, 낡은 테스트를 지운다. 전환 때까지 모아 두지 않는다. Unity 판이 아직 쓰는 것은 그 사용이 끝날 때까지 둔다. 끝난 구현 계획 문서도 지운다.

## MonoGame 판

- MonoGame 3.8.6.1로 고정한다. MonoGame 참조는 실행 프로그램(Host)에만 둔다.
- 테스트의 프레임 진행은 MonoGame 내부 `SdlRunLoop` 호출에, 한글 조합 입력은 SDL2 직접 호출에 기댄다. 각각 한 곳에만 두고, 버전을 올릴 때 이 둘을 먼저 확인한다.
- 그림은 PNG를 그대로 읽고, 맵은 LDtk 파일을 그대로 읽는다. 변환 단계를 두지 않는다.
