# ROOTBORN 세대 간 유산 시스템 Goal Prompt

ROOTBORN의 세대 전환 시스템에 "유산(Legacy)" 메커닉을 설계하고 싶다.

현재 게임은 세대가 바뀌며 플레이어가 이전 세대와 다음 세대를 넘나드는 구조다. 이전 세대에서 한 행동이 다음 세대에도 의미 있는 흔적으로 남아야 한다. 예시는 다음과 같다.

- 이전 세대가 모은 재산 일부가 다음 세대의 시작 자원, 농장 상태, 도구 접근성에 영향을 준다.
- 이전 세대가 반복한 행동이나 성취가 다음 세대의 특성, 지식, 능력 보정으로 이어진다.
- 특정 작물, 도구, 유물, 물고기, 제작품, 기록물이 박물관/가문관/기념관에 전시되어 세대를 넘어 보존된다.
- 조상의 업적이 `LineageBook` 또는 별도 기록 시스템에 남고, 이후 세대가 이를 읽거나 활용할 수 있다.
- 모든 영향은 단순 보너스가 아니라 플레이어가 "내가 이전 세대에 남긴 것이 세계에 남아 있다"고 느끼게 해야 한다.

## 중요 제약

- 엔티티 데이터-드리븐 원칙을 반드시 지킨다.
- 작물, 도구, 자원, 지식, 특성, 세대 프로필, 상태, 레시피, 유산 항목은 모두 ScriptableObject 기반이어야 한다.
- `if (cropId == "X")`, `switch(toolId)`, ID enum, 작물/도구/유산별 C# 하드코딩 분기는 금지한다.
- 신규 데이터는 `Assets/Data/{...}` 경로에 두고 `GameDataRegistry.asset` 등록 구조를 따른다.
- 세대 전환은 기존 `GenerationManager`, `GenerationProfile`, `HeirData`, `HeirTrait`, `LineageBook`, `KnowledgeNode` 구조와 자연스럽게 연결한다.
- 구현 전 TDD 시나리오를 먼저 설계한다.

## 원하는 결과

1. 세대 간 유산 시스템의 핵심 게임 디자인을 제안한다.
2. "돈/자원 계승", "특성/능력 계승", "박물관/전시/기록물", "세계 상태 변화"를 각각 어떤 방식으로 다룰지 정리한다.
3. 2~3개의 접근안을 비교하고 추천안을 고른다.
4. 추천안 기준으로 필요한 SO 타입, 런타임 서비스, 저장 데이터, UI 흐름, 테스트 시나리오를 설계한다.
5. 1차 구현 범위와 후속 확장 범위를 나눈다.
6. 플레이어가 세대 전환 시 어떤 선택을 하고, 다음 세대에서 어떤 보상을 체감하는지 구체적인 예시를 포함한다.

## 추천 방향

`LegacyDefinition + LegacyTriggerBase[] + LegacyRewardBase[]` 구조를 중심으로 한다.

이전 세대의 행동은 `LegacyTrigger`가 판정하고, 세대 전환 시 `LegacyReward`가 다음 세대 시작 상태, `HeirTrait` 후보, `Knowledge` 해금, 박물관 전시 상태, 농장/세계 상태에 영향을 준다.

박물관이나 기념관은 단순 장식이 아니라 `LegacyExhibitDefinition` 또는 유사 SO로 정의된 영구 전시/기록 시스템으로 만든다. 전시된 항목은 이후 세대의 지식, 명성, 시작 선택지, NPC 반응 등에 연결될 수 있게 한다.

이 시스템은 다음 흐름으로 설계한다.

```text
이전 세대의 성취
-> 유산 조건 판정
-> 가문 기록/전시/계승 보상 생성
-> 다음 세대 시작 상태에 반영
```

## 설계 관점

상속을 하나로 뭉뚱그리지 말고 네 갈래로 나눈다.

- 물질 유산: 돈, 자원, 도구, 씨앗, 저장고, 농장 시설
- 혈통/특성 유산: `HeirTrait`, 능력 보정, 체질, 학습 성향
- 지식/기술 유산: `KnowledgeNode`, 제작법, 농사 기술, 도구 해금
- 세계/전시 유산: 박물관 전시, 가문 기록, 기념물, 농장 지형/시설 흔적

이렇게 나누면 돈, 특성, 박물관, 농장 상태를 전부 같은 `LegacyDefinition` 계열로 처리하면서도 하드코딩을 피할 수 있다.
