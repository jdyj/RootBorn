# 플레이 시간과 지루한 구간을 시뮬레이션으로 재기 — 설계

- 날짜: 2026-11-13. 상태: 사용자 확인 대기(질문 없이 추천안으로 썼다. 대신 정한 것은 9절).
- 사용자 지시(2026-11-13): "하루 길이나 지루한 구간은 시뮬레이션을 통해서 어느정도 몇시간 어떻게 걸릴지 판단이 나올거같은데 그렇게하도록 시뮬레이션 개선이 필요해", "수치 균형도 시뮬레이션으로 어느정도 밸런스 잡을 수 있도록 할 예정이야".
- 근거 종류: 이 설계가 내는 숫자는 모두 **자동 테스트(실제 플레이 아님)** 이다. 사람이 느끼는 재미를 재지 못한다 — "여기를 사람이 해 봐야 한다"는 후보를 좁혀 줄 뿐이다.

## 1. 무엇을 알고 싶은가

1. **얼마나 걸리나** — 메인 체인 끝, 첫 알바, 성인기, 시설 레벨 2·3 같은 지점에 닿기까지 실제 시간으로 몇 분·몇 시간인가.
2. **하루가 어떻게 쓰이나** — 실제 10분인 하루에서 걷기, 활동을 기다리기, 미니게임, 화면 읽기, 할 것이 없어 시간만 보내기가 각각 얼마인가.
3. **어디가 지루한가** — 새로운 것이 오래 안 나오는 구간, 같은 행동만 되풀이하는 구간, 할 수 있는 것이 자는 것뿐인 구간.
4. **수치를 바꾸면 위 셋이 어떻게 달라지나** — `data/`를 고치기 전에 견줘 본다(수치 균형 작업과 이어진다).

## 2. 지금 있는 것 (main에서 확인)

- **자동 플레이어** `game/tests/Rootborn.Simulation.Tests`: 창 없이 실제 게임 루프를 프레임 단위로 돌리며 정책(`PlayPolicies` — 메인 체인 우선, 학교 밖 등)이 관찰(`PlayObserver`)에서 행동을 고른다. 걸음마다 날·분·맵·맨 위 화면·행동을 적는다(`PlayStep`, `output/simulation/<이름>/play.txt`, `summary.md`). 불변식 검사가 목적이고 **시간은 재지 않는다.**
- **수치 균형 시뮬레이터** `game/tests/Rootborn.Balance.Tests`(브랜치 `balance-simulator`, 아직 main 밖): `GameSession` 명령만으로 여러 날을 돌려 돈을 잰다. 걷는 시간·미니게임 시간은 **가정 값**(축)이다. 화면과 걷기가 없다.
- **시간 규칙**: 하루는 실제 10분(`data/time`의 `TimeDefinition`), 07:00 시작·22:00 취침(`game/time.json`). 혼자 할 때 메뉴·대화 중에는 시계가 멈춘다.
- 둘 다 원격 장치에서 돌린다(`Scripts/remote-test/run.sh`).

빈 곳: 걷기까지 실제로 하는 쪽은 시간을 안 재고, 시간을 다루는 쪽은 걷기를 가정한다. 그리고 어느 쪽도 "새로운 것이 얼마나 자주 나오는가"를 보지 않는다.

## 3. 만들 것 — 속도 기록과 속도 보고서

자동 플레이어에 **속도 기록**(`PaceRecorder`)을 붙이고, 한 판이 끝나면 **속도 보고서**(`output/simulation/pace/<판 이름>/`)를 낸다. 게임 코드는 고치지 않는다(테스트 프로젝트 안. 필요한 값이 `GameSession` 조회에 없으면 조회를 더한다).

### 3.1 실제 시간을 어떻게 어림하나

한 걸음(행동 하나)마다 두 가지를 더한다.

- **게임이 돈 시간** = 그 걸음이 돈 프레임 수 ÷ 초당 프레임(고정 간격). 걷기, 문, 활동을 기다리기, 미니게임이 여기에 든다. 가정이 아니라 실제로 돈 값이다.
- **사람이 쓰는 시간** = 자동 플레이어는 0초에 읽고 누르지만 사람은 아니다. 이것은 가정이고 **축**으로 둔다(사용자 방침: 한 값으로 고정하지 않는다).
  - 글 읽기: 화면에 새로 나온 글자 수 ÷ 읽는 속도(느림·보통·빠름·읽지 않고 넘김).
  - 고르기: 선택지·단추가 있는 화면에서 한 번 고르는 데 드는 시간(짧게·보통·오래).
  - 미니게임: 자동 풀이가 쓴 시간이 아니라 제한 시간의 몫(0.25·0.5·1.0 — 균형 시뮬레이터와 같은 축).

보고서는 축 값마다 한 줄을 내고, 기준 값(보통·보통·0.5)을 표시한다. 그래서 "빨리 넘기는 사람은 40분, 다 읽는 사람은 1시간 20분" 같은 범위가 나온다.

### 3.2 무엇에 쓴 시간인가 — 분류

걸음마다 시간을 한 분류에 넣는다. 분류는 맨 위 화면과 행동 종류에서 정한다(화면 id·엔티티 id로 분기하지 않고 화면 등록의 성질 — 층, 이동을 막는지, 미니게임인지 — 과 행동의 `Category`를 쓴다).

| 분류 | 뜻 |
|---|---|
| 걷기 | 화면 없이 이동 |
| 활동 중 | "하는 중"으로 시계가 흐르는 동안 |
| 미니게임 | 미니게임 화면 |
| 읽기·고르기 | 대화, 이벤트, 결과 같은 화면(사람이 쓰는 시간) |
| 살펴보기 | 가방·수첩·기록 같은 화면을 연 시간 |
| 할 것 없음 | 할 수 있는 행동이 "기다리기·자기"뿐인 채 흐른 시간 |
| 잠 | 잠자리에 든 뒤 다음 날까지 |

### 3.3 새로운 것 — 지루함의 근거

"새로운 것"을 사건으로 적는다. 종류는 등록 방식으로 더한다(클래스 하나 + 한 줄).

- 처음 연 화면, 처음 들어간 맵, 처음 만난 NPC, 처음 본 대사
- 퀘스트·체인 단계가 넘어감, 캠페인 날이 넘어감
- 처음 한 활동·알바·미니게임 종류, 처음 받은 아이템 종류
- 특성·기술이 단계에 닿음, 진로 후보가 열림, 시설 레벨이 오름, 가구가 풀림

여기서 재는 것:

- **새로운 것 사이의 간격**(실제 시간). 가장 긴 간격 열 개를 "언제(몇 일째 몇 시), 그동안 무엇을 했는지(분류별 시간과 되풀이한 행동)"와 함께 낸다.
- **되풀이** — 같은 행동이 연달아 몇 번, 하루에 몇 번.
- **빈 날** — 새로운 것이 하나도 없는 날의 수와 처음 나오는 날.
- **할 것 없음의 몫** — 하루 중 몇 분.

### 3.4 지점까지 걸린 시간

지점은 데이터에서 저절로 얻는다(이름을 코드에 적지 않는다): 각 퀘스트 체인의 끝, 캠페인의 각 날, 성인이 됨, 시설 레벨마다, 진로 후보가 열림. 지점마다 "몇 일째, 실제 누적 시간(축 값별)"을 낸다.

### 3.5 내는 것

`output/simulation/pace/<판 이름>/`

- `report.md` — 한 장 요약: 지점까지 걸린 시간 표, 하루 시간 쓰임 표(날마다), 가장 긴 지루한 구간 열 개, 되풀이 상위, 가정 값.
- `timeline.csv` — 걸음마다(날, 시각, 분류, 게임이 돈 초, 사람이 쓰는 초, 행동, 새로운 것).
- `novelty.csv` — 새로운 것의 사건 목록.

저장소에 커밋하지 않는다(`output/`).

## 4. 누가 플레이하나 — 정책

지금 정책(메인 체인 우선, 학교 밖)에 더해 **플레이어 유형**을 정책으로 둔다. 정책은 엔티티 id를 모른다(관찰에서 고른다).

- 이야기만 따라가는 사람(지금의 메인 체인 우선)
- 돈을 모으는 사람(보상이 가장 큰 일을 되풀이)
- 이것저것 해 보는 사람(안 해 본 것 우선 — 새로운 것이 가장 빨리 나오는 위쪽 한계)
- 한 가지만 파는 사람(같은 활동만 — 지루함의 아래쪽 한계)

유형마다 같은 보고서를 내고 나란히 견준다. "이것저것 해 보는 사람조차 12일째부터 새로운 것이 없다"면 콘텐츠가 거기서 바닥난 것이다.

## 5. 긴 기간 — 두 층

프레임 단위로 100일을 돌리면 오래 걸린다(하루 = 실제 10분 = 3만 6천 프레임).

- **가까운 층(프레임 단위, 처음 N일)**: 자동 플레이어 그대로. 걷기와 화면이 실제로 돈다. 메인 체인과 처음 며칠의 속도를 본다. N은 설정(기본 7일).
- **먼 층(명령 단위, 100일까지)**: 균형 시뮬레이터가 이미 `GameSession` 명령으로 도는 판에 같은 속도 기록을 붙인다. 걷는 시간은 가까운 층에서 **잰 값**(지점 사이 평균)을 가정 값 대신 넣는다. 그래서 균형 시뮬레이터의 걷기 가정이 실제 맵에서 잰 값으로 바뀐다.

먼 층은 균형 시뮬레이터가 main에 들어온 뒤에 만든다.

## 6. 수치를 바꿔 견주기 (수치 균형과 잇기)

`data/`를 고치지 않고 수치를 바꿔 돌린다.

- **덮어쓰기 폴더**: `data/`와 같은 모양의 작은 폴더(바꿀 엔티티만)를 실행 인자·환경 변수로 준다. 로더가 `data/` 위에 덮어 읽는다(문구의 `game/localization`이 `data/localization`을 덮는 것과 같은 방식). 게임 실행에는 쓰지 않고 시뮬레이션 테스트에서만 쓴다.
- 보고서는 **바꾸기 전과 후를 나란히** 낸다: 지점까지 시간, 하루 수입(균형 시뮬레이터), 지루한 구간.
- 마음에 드는 값이 나오면 사람이 `data/`에 옮긴다. 시뮬레이터가 `data/`를 고치지 않는다(수치는 사용자 결정).

## 7. 범위 검사 — 값은 사용자가 정한다

균형 시뮬레이터와 같은 방식으로 범위를 데이터 파일에 둔다(처음에는 비어 있어 아무것도 막지 않는다). 예: "이야기만 따라가면 메인 체인이 실제 30~90분", "새로운 것 없는 구간이 실제 15분을 넘지 않는다", "할 것 없음이 하루의 10%를 넘지 않는다". 첫 보고서를 본 뒤 사용자가 값을 정하면 그때부터 테스트가 막는다.

## 8. 순서

1. **속도 기록과 보고서**(가까운 층): `PaceRecorder`, 분류, 새로운 것 등록, 지점, 보고서 세 파일. 지금 있는 두 정책으로 메인 체인과 7일을 돌려 첫 보고서를 낸다. 원격 장치에서 돌린다.
2. **플레이어 유형 정책 넷**과 나란히 보는 보고서.
3. (균형 시뮬레이터가 main에 들어온 뒤) **먼 층**과 걷기 가정을 잰 값으로 바꾸기.
4. **덮어쓰기 폴더**와 전후 비교.
5. 사용자가 범위 값을 정하면 **범위 검사**.

1단계가 끝나면 첫 숫자가 나온다 — 그것을 보고 2단계 이후를 고칠 수 있다.

## 9. 대신 정한 것 (사용자가 뒤집을 수 있다)

1. 사람이 쓰는 시간은 가정이고 축으로 둔다. 기준 값은 읽기 보통(분당 400자), 고르기 2초, 미니게임 몫 0.5 — 표를 읽기 쉽게 하는 표시일 뿐이다.
2. "지루함"을 새로운 것 사이의 간격, 되풀이, 할 것 없음 셋으로 잰다. 재미 자체는 재지 않는다.
3. 플레이어 유형 넷.
4. 가까운 층 기본 7일.
5. 수치 바꾸기는 덮어쓰기 폴더로, 시뮬레이터는 `data/`를 고치지 않는다.
6. 범위 값은 비워 둔다.

## 10. 확인하지 못한 것

- 자동 플레이어가 대화·이벤트 화면에서 새로 나온 글자 수를 지금 관찰에서 얻을 수 있는지(없으면 화면의 글자 노드에서 센다).
- 창 없는 시험 세계(`HeadlessBody`)의 걷기 시간이 실제 창(Host)과 같은지 — 같은 Core 걷기 규칙을 쓰지만 대조하지 않았다. 1단계에서 Host 테스트 하나로 같은 길의 프레임 수를 견준다.
- 지금 정책이 성인기까지 스스로 갈 수 있는지(메인 체인까지는 간다). 못 가면 먼 층이 맡는다.
- 7일을 프레임 단위로 돌리는 데 원격 장치에서 걸리는 시간.
