# 착용 칸 캐릭터 설계 (2026-11-07)

사용자 요청: "캐릭터 얼굴, 옷, 모자 및 악세사리 등 착용가능하게", "너무 결합력을 높히지 말았으면". 그림은 사용자가 다른 세션에서 만든다. 이 설계는 그림이 들어오면 데이터만 추가해 쓰는 구조를 만든다.

## 지금 구조와 문제
- `GrowingCharacterAppearanceDefinition` 하나가 몸·머리·옷 그림 세 장을 묶은 "모습"이다. 옷장은 같은 몸·머리를 가진 모습 중 하나를 고른다. 얼굴, 모자, 액세서리를 따로 바꿀 수 없고, 머리 하나를 추가하면 단계 × 옷 수만큼 조합이 늘어난다.
- 성장 단계 규칙(최소 학생 일차, 어른, 일터)이 모습 데이터에 붙어 있다.
- `PlayerController`가 외형 분리 지점(`PlayerCharacterVisualAdapter`)과 옛 부위 조합 클래스(`CharacterPartComposer`, `CharacterPartAnimator`, `CharacterPartAnimationClipDefinition`)를 함께 직접 다룬다. 도구 휘두르기와 낚시 애니메이션이 옛 클래스에 묶여 있다.
- 그림 형식: 시트마다 4행(방향) × 6열(프레임). 이 형식은 그대로 쓴다.

## 목표 구조

### 1. 플레이어 본체와 외형의 분리
- 본체(`PlayerController`, 상호작용, 진행도)는 그림을 모른다. 이동 입력, 바라보는 방향, 행동(도구 사용 등) 상태만 `ICharacterVisualView`로 알린다.
- 외형(`ICharacterVisualView` 구현)이 그 상태로 프레임을 고른다. 외형 구현을 통째로 바꿔도 본체 코드는 바뀌지 않는다.
- 옛 부위 조합 클래스 6개를 지우고, 도구·낚시 애니메이션은 외형이 받는 "행동" 신호로 옮긴다.

### 2. 데이터 (모두 ScriptableObject, 코드 분기 없음)
- **성장 단계** (`CharacterGrowthStageDefinition`): id, 표시 이름, 적용 규칙(최소 학생 일차, 어른 여부), 몸 그림. 지금 모습 데이터에 붙은 규칙을 옮긴다.
- **착용 칸** (`WearableSlotDefinition`): id, 표시 이름, 그리는 순서, 비어 있어도 되는지, 기본 착용품, 이 칸이 차면 숨길 칸 목록(예: 모자가 머리 윗부분을 가림). 칸 종류는 enum이 아니라 데이터라서 안경·가방 같은 새 칸도 코드 수정 없이 추가한다.
- **착용품** (`WearableDefinition`): id, 표시 이름, 칸, 성장 단계별 그림 목록, 착용 가능 조건, 일터 자동 착용(지금의 요리사·인테리어 유니폼 동작).
- 처음 칸: 얼굴, 머리, 상의(지금의 옷 한 벌 그림), 모자, 액세서리. 하의는 그림이 상하의로 나뉘면 데이터로 추가한다.

### 3. 규칙은 엔진 무관 순수 C# (헌법 13번)
- 입력: 성장 단계 id, 칸 목록(순서·숨김 규칙), 착용 상태(칸 → 착용품 id), 각 착용품이 가진 단계 목록, 일터 id.
- 출력: 이번 단계에 그릴 층 목록(칸 순서대로 착용품 id). 그 단계 그림이 없는 착용품은 빼거나 칸의 기본값으로 바꾼다.
- 착용 검증(칸 일치, 조건 충족)과 저장 데이터 변환도 여기에 둔다. Unity 없이 테스트한다.

### 4. 착용 상태 저장과 이전
- 슬롯 폴더에 착용 상태 파일 하나(칸 id → 착용품 id). 옷장에서 바꿀 때 바로 저장한다.
- 이전: 기존 옷장 파일(`growing-wardrobe-*.json`)과 생성 화면 메타데이터(`outfit:<몸 id>`)를 읽어 처음 한 번 새 형식으로 옮긴다. 기존 세이브가 깨지지 않게 한다.
- 멀티플레이: 지금의 외형 id 동기화 대신 착용품 id 목록을 동기화한다.

### 5. 화면
- 외형은 칸 수만큼 SpriteRenderer 층을 만들고 칸 순서로 정렬한다.
- 생성 화면과 옷장은 같은 착용품 데이터를 칸별로 보여 준다. 착용품을 추가하면 두 화면에 자동으로 나온다. 그림이 하나뿐인 칸은 화살표를 숨긴다(지금 생성 화면과 같은 규칙).

## 지금 그림의 이전
- 몸 3장 → 성장 단계 3개의 몸 그림.
- 머리 3장(단계별 짧은 갈색) → 머리 칸 착용품 1개, 단계별 그림 3장.
- 옷 7장 → 상의 칸 착용품 7개(평상복·사복·교복·어른 평상복·정장·요리사·인테리어). 요리사·인테리어는 일터 자동 착용.
- 얼굴·모자·액세서리 칸은 비어 있어도 되는 칸으로 시작한다. 그림이 들어오면 착용품 데이터만 추가한다.

## 테스트
- 순수 C#: 층 결정(순서, 숨김, 단계 그림 없음 처리, 일터 자동 착용), 착용 검증, 저장 형식 왕복, 기존 옷장·생성 화면 데이터 이전.
- EditMode: 데이터 연결(모든 착용품의 칸·단계 그림 유효), 기존 7개 모습이 그대로 재현되는지.
- PlayMode: 생성 화면에서 칸별로 고르고 시작 → 마을 캐릭터 층 확인 → 옷장에서 마우스로 바꾸기 → 불러오기 후 유지. 실제 입력으로 진행하고 Game View 스크린샷으로 확인한다.

## 하지 않는 것
- 그림 제작(사용자가 다른 세션에서 진행).
- 피부색 같은 색 바꾸기. 필요하면 착용품이나 칸에 색 정보를 더하는 후속 작업으로 한다.
