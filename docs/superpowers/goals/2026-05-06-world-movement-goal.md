# 월드 이동 축 복구 goal

## 목표

`MOV`, `CAM`, `MAP`, `UI` 시나리오로 구성된 1차 `이동 축 전용 스위트`를 실패 테스트부터 작성하고, 최소 구현으로 모두 통과시킨다. 이후 동일한 방식으로 전체 테스트 스위트 확장이 가능해야 한다.

## 비목표

- 이번 goal에서 전체 게임 시스템을 한 번에 완성하려 하지 않는다.
- 이동 축과 무관한 대규모 리팩터링을 하지 않는다.
- 임시 수동 QA로 자동화 테스트를 대체하지 않는다.

## 절대 헌법

1. `Assets/**/*.cs` 신규/수정은 Unity 안전 경로를 따른다. 디스크 직접 쓰기 금지 원칙을 어기지 않는다.
2. 모든 신규 동작 또는 버그 수정은 실패 테스트 먼저, 구현 다음 순서로 진행한다.
3. 엔티티 ID 분기, 하드코딩된 씬/작물/도구별 특수 처리로 문제를 덮지 않는다.
4. 기존 사용자 변경분을 임의로 되돌리지 않는다.
5. 한 번의 반복에서는 하나의 원인군만 해결한다. 이동, 카메라, 포털, UI를 무차별로 섞어 수정하지 않는다.
6. 관련 기존 회귀 테스트가 깨지면 완료로 인정하지 않는다.

## 1차 시나리오 카탈로그

### MOV

- `MOV-001` 입력 벡터가 주어지면 플레이어가 예상 방향으로 이동한다.
- `MOV-002` 대각 입력은 정규화되어 축 이동보다 빨라지지 않는다.
- `MOV-003` 충돌체가 있는 경우 Rigidbody2D 기반 이동이 벽을 관통하지 않는다.
- `MOV-004` 입력이 0이면 이동이 멈추고 마지막 facing/idle 상태가 안정적으로 유지된다.

### CAM

- `CAM-001` 카메라가 플레이어를 일정 시간 내 추적한다.
- `CAM-002` 씬 전환 후에도 카메라가 새 씬의 플레이어를 계속 추적한다.
- `CAM-003` 포털 이동 직후 플레이어가 화면 밖으로 사라지지 않는다.

### MAP

- `MAP-001` `Farm -> Town` 포털 이동이 성공한다.
- `MAP-002` `Town -> House` 포털 이동이 성공한다.
- `MAP-003` `House -> Town` 또는 `Town -> Farm` 복귀 이동이 성공한다.
- `MAP-004` 각 이동 후 `SpawnId` 위치 재배치가 정확하다.
- `MAP-005` 씬 전환 중 플레이어 인스턴스가 중복 생성되지 않는다.

### UI

- `UI-001` HUD 필수 요소가 씬 진입 후 유효하다.
- `UI-002` Dialogue/Overlay가 열린 뒤 닫히면 이동 가능 상태가 복구된다.
- `UI-003` 씬 전환 후 HUD 참조가 깨지지 않는다.

## 반복 루프

반드시 아래 순서를 지킨다.

1. 현재 실패 테스트와 미구현 시나리오를 식별한다.
2. 가장 작은 단위의 실패 테스트를 추가하거나 기존 실패를 고정한다.
3. 실제로 테스트를 실행해 실패를 확인한다.
4. 해당 실패를 해결하는 최소 구현만 적용한다.
5. 이동 축 전용 스위트와 관련 기존 회귀 테스트를 다시 실행한다.
6. 남은 실패를 `이동`, `카메라`, `포털`, `UI`, `씬/자산 와이어링`, `테스트 결함` 중 하나로 분류한다.
7. 실패가 남아 있으면 다음 루프로 돌아간다.
8. 모든 종료 조건을 만족할 때만 멈춘다.

## 테스트 실행 순서

반복마다 아래 우선순위를 따른다.

1. 가장 작은 관련 EditMode 테스트
2. 해당 기능의 PlayMode 단일 테스트
3. 이동 축 전용 PlayMode 묶음
4. 이동 축과 직접 연결된 기존 회귀 테스트 묶음

가능하면 한 번에 전체 테스트를 돌리기 전에 더 작은 범위로 실패를 수렴시킨다.

## 실패 분류 규칙

- `이동`: 입력, 속도, 정지, 충돌, facing
- `카메라`: follow, offset, 타깃 상실, 프레이밍
- `포털`: 전환 트리거, 씬 로드, 스폰 위치, 플레이어 생존
- `UI`: HUD null, 오버레이 미표시, 입력 잠금 미복구
- `씬/자산 와이어링`: 씬 누락, 오브젝트 이름 불일치, 필수 컴포넌트 누락
- `테스트 결함`: 테스트 자체가 잘못된 가정 또는 불안정한 장치 의존

한 루프에서 둘 이상의 원인군을 동시에 해결하려 하지 않는다.

## 권장 작업 순서

1. 기존 이동 축 코드와 테스트 인벤토리 작성
2. 시나리오 ID를 기준으로 테스트 공백 식별
3. 가장 작은 실패 테스트 추가
4. 테스트 실행
5. 최소 구현
6. 회귀 실행
7. 다음 시나리오로 이동

## 종료 조건

- `MOV/CAM/MAP/UI` 1차 카탈로그가 모두 테스트로 존재한다.
- 이동 축 전용 스위트가 전부 통과한다.
- 관련 기존 EditMode/PlayMode 회귀 테스트가 통과한다.
- skip, FIXME, 미정 상태 없이 결과가 정리된다.
- 마지막 보고에 실행한 테스트 목록과 통과 여부가 기록된다.

## 최종 보고 형식

최종 보고에는 반드시 아래를 포함한다.

- 이번 반복에서 새로 추가한 시나리오 ID
- 수정한 런타임 코드와 테스트 파일
- 실행한 테스트 명령 또는 테스트 대상
- 통과/실패 결과
- 아직 남은 실패가 있다면 다음 루프의 첫 대상 원인군

## 장기 확장 규칙

1차 goal이 끝나면 동일한 루프를 전체 테스트 스위트로 확장한다.

- 다른 코어 루프도 prefix 기반 시나리오로 문서화한다.
- 신규 기능은 대응 시나리오 등록 없이는 완료로 인정하지 않는다.
- 전체 스위트 확장 전에도 현재 이동 축 스위트는 항상 회귀 집합으로 유지한다.
