# Location Time State Goal Prompt

아래 프롬프트를 goal 세션에 그대로 붙여 넣고 진행한다.

```text
ROOTBORN Unity 프로젝트에서 "시간대, 월드 상태, 장소 숙련도/친밀도, NPC 스케줄, 퀘스트/단서 상태에 따라 장소의 현재 상태와 가능한 활동/NPC/단서/상호작용이 달라지는 장소 시간대 상태 시스템"을 설계/구현/검증해줘.

핵심 의도:
- 장소 숙련도/친밀도는 "플레이어가 그 장소를 얼마나 이해하고 활용했는가"를 누적하는 장기 성장도다.
- 이번 goal의 장소 시간대 상태는 "지금 이 시간과 조건에서 이 장소가 어떤 상태인가"를 결정하는 현재 상태 시스템이다.
- 같은 장소라도 오전/오후/저녁, 월드 상태, NPC 스케줄, 장소 숙련도, 퀘스트/단서 진행에 따라 가능한 활동과 상호작용이 달라져야 한다.
- 플레이어가 같은 장소를 다른 시간대에 다시 방문할 이유를 만들어야 한다.
- 새 장소 상태는 C# 코드 수정 없이 ScriptableObject 데이터 추가와 Registry 등록만으로 추가 가능해야 한다.

헌법 규칙:
- AGENTS.md와 `.claude/rules/*`를 따른다.
- `Assets/**/*.cs`를 외부 디스크 쓰기로 직접 수정하지 않는다. C# 신규/수정은 반드시 Unity MCP `script-update-or-create` 또는 Unity Editor 안전 경로를 사용한다.
- 모든 게임 엔티티는 100% ScriptableObject 데이터 기반이어야 한다.
- locationId, stateId, timeSlotId, npcId, activityId, clueId, questId별 `if/switch` 분기, enum 기반 엔티티 분기, 장소 상태별 C# 클래스 생성은 금지한다.
- 장소 상태 조건, 우선순위, 충돌 해결, 효과, UI 표시 규칙은 SO 데이터와 전략 배열로 표현한다.
- 장소 상태 발견/보상/단서/활동/퀘스트/도감 결과는 저장/로드 후 중복 적용되면 안 된다.
- TDD로 진행한다. 먼저 실패하는 테스트를 만들고 실패를 확인한 뒤 구현한다.
- 성능/최적화 동시 설계 원칙을 따른다.
- 기존 dirty 변경을 되돌리지 않는다.

권장 데이터 구조:
- `LocationStateDefinition`
  - 장소, 표시명, 설명, 시간대, 우선순위, 상태 배지, 관련 NPC/활동/단서/퀘스트/오브젝트/포탈, UI 표시 정책을 정의한다.
- `LocationStateConditionBase[]`
  - 시간대, 월드 상태, 장소 숙련도/친밀도, NPC 스케줄, 퀘스트 상태, 단서 상태, 도감 상태, 아이템 보유를 일반 조건으로 평가한다.
- `LocationStateEffectBase[]`
  - 가능한 활동, 등장 NPC, 상호작용 오브젝트, 소문/단서 source, 상점 품목, 포탈, 하루 이벤트 후보를 일반 효과로 제공한다.
- `LocationStateConflictPolicyDefinition`
  - 같은 장소에 여러 상태가 동시에 조건을 만족할 때 우선순위, 병합, 대체, 숨김 정책을 데이터로 정의한다.
- `LocationStateProgress`
  - saveSlot + player identity 기준으로 상태 발견 여부, 상태별 첫 방문 날짜, 상태별 보상 수령 여부, 오늘 발견 요약을 저장한다.
- `LocationStateSummaryModel`
  - 지도 UI, 장소 UI, 장소 진입 배너, 하루 결과 UI, 월드 로그 UI에서 공통으로 사용하는 표시 모델이다.

초기 장소 상태 예시:
- 도서관 오전 상태
  - 조건: 시간대 오전, 도서관 개방
  - 효과: 사서 등장, 자료 정리 활동, 기본 열람
- 도서관 저녁 상태
  - 조건: 시간대 저녁, 도서관 숙련도 2 이상
  - 효과: 조용한 심화 조사, 오래된 기록 단서 후보
- 도서관 자료실 심화 상태
  - 조건: 자료실 개방 WorldStateFlag, 시간대 저녁, 도서관 숙련도 3 이상
  - 효과: 오래된 기록 조사, 탐험·정보형 단서, 사서 후속 대화
- 공방 오후 상태
  - 조건: 시간대 오후, 공방 작업대 등장
  - 효과: 수리 연습, 납품 준비, 작업 관리자 대화
- 공방 마감 상태
  - 조건: 시간대 저녁, 공방 숙련도 2 이상
  - 효과: 작업대 정리, 숨은 부품 단서, 기술형 후속 이벤트
- 상점 저녁 상태
  - 조건: 시간대 저녁, 상점 신뢰도 또는 장소 숙련도 기준 충족
  - 효과: 마감 정리, 배달 도움, 단골 이벤트
- 골목 저녁 상태
  - 조건: 시간대 저녁, 숨은 길 단서 또는 월드 상태 활성화
  - 효과: 수상한 소문, 골목 흔적, 숨은 길 포탈 힌트

UI 요구:
- 지도/장소 UI에는 현재 장소 상태 이름과 상태 배지를 표시한다.
- 장소 UI에는 현재 상태에서 가능한 활동, 등장 NPC, 미확인 단서, 열린 상호작용을 표시한다.
- 장소 진입 시 짧은 상태 배너를 표시할 수 있다.
  - 예: `도서관: 조용한 저녁 열람 시간`
  - 예: `공방: 납품 준비 시간`
- 하루 결과 UI에는 오늘 발견한 장소 상태와 새로 열린 시간대 활동/단서를 표시한다.
- 월드 로그 UI에는 장소별 발견한 상태와 아직 미확인 상태를 표시한다.
- UI는 특정 locationId/stateId/timeSlotId를 직접 알지 않고 `LocationStateSummaryModel`을 렌더링한다.
- 잠긴 상태는 `???`와 일부 힌트만 표시한다.
- Modern UI Style2 공통 패널 규약을 따른다.
- 1920x1080 기준에서 장소명, 상태명, 가능 활동, 등장 NPC, 조건, 버튼 텍스트가 겹치거나 잘리지 않아야 한다.
- UI는 문서 목업만 만들고 끝내면 안 된다. PlayMode에서 실제로 열리고 클릭 가능해야 한다.

확장성 검증:
- 새 장소 상태는 C# 코드 수정 없이 ScriptableObject 데이터 추가와 Registry 등록만으로 추가 가능해야 한다.
- 테스트용 신규 `LocationStateDefinition`을 1개 이상 추가하고, 기존 런타임 코드를 수정하지 않은 상태에서 조건 평가, 상태 표시, 효과 적용, 저장/로드가 동작하는지 검증한다.
- 한 장소는 여러 시간대 상태를 가질 수 있어야 한다.
- 하나의 장소 상태는 여러 조건과 여러 효과를 가질 수 있어야 한다.
- 같은 상태가 활동, NPC, 단서, 퀘스트, 오브젝트, 포탈, 상점 품목을 동시에 제공할 수 있어야 한다.
- 여러 상태가 동시에 조건을 만족할 때 우선순위/병합/대체 정책이 데이터 기반으로 동작해야 한다.
- 장소 숙련도/친밀도, 월드 상태, NPC 스케줄, 소문/단서, 퀘스트 체인과 연결 가능해야 한다.
- 최종 보고에는 "장소 시간대 상태 확장성 검증 체크리스트"를 포함하고, SO만으로 추가한 테스트 장소 상태의 실제 플레이 검증 결과를 기록한다.

최우선 실제 플레이 검증 원칙:
- 이 goal은 실제 유저가 플레이하듯 검증하지 않으면 완료로 인정하지 않는다.
- 최소 1개 이상의 PlayMode E2E는 저장 슬롯 UI에서 시작해 실제 키보드 이동, 실제 장소 방문, 실제 NPC/오브젝트/활동/지도/장소 UI 상호작용, 시간대 변화, 장소 상태 변화 확인, 저장/로드 재진입을 모두 거쳐야 한다.
- 테스트에서 LocationStateProgress, LocationAffinityProgress, WorldStateProgress, QuestLog, SaveData 상태를 직접 세팅해서 성공 처리하면 실패다.
- 플레이어 Transform 직접 이동, 내부 메서드 직접 호출, 씬 강제 로드, 저장 데이터 직접 주입, UI 없이 도메인 API 직접 호출로 실제 플레이 경로를 대체하면 완료로 보고하지 않는다.
- 최종 보고 전에 "실제 플레이 방식 상호작용 검증 체크리스트"를 반드시 작성하고, 각 항목을 PASS/FAIL로 표시한다.

실제 플레이 방식 상호작용 검증 체크리스트:
- 저장 슬롯 UI에서 새 게임 또는 기존 슬롯을 실제 UI 경로로 시작했는가?
- 플레이어 이동이 Transform 직접 세팅이 아니라 키보드/입력 시스템 경로로 수행됐는가?
- 같은 장소를 서로 다른 시간대에 실제 이동으로 방문했는가?
- 시간대 변화가 내부 시간 직접 세팅이 아니라 실제 하루/시간 진행 또는 사용자 흐름에 가까운 테스트 경로로 발생했는가?
- 장소 UI/지도 UI/진입 배너에서 현재 장소 상태가 표시됐는가?
- 현재 상태에 따라 가능한 활동, 등장 NPC, 단서, 상호작용 중 최소 2개 이상이 달라졌는가?
- 장소 숙련도/친밀도 또는 월드 상태 조건에 따라 같은 시간대라도 다른 상태가 열리는지 확인했는가?
- 저장 슬롯 UI 재진입 후 같은 슬롯을 로드했을 때 상태 발견 여부, 보상 수령 여부, 미확인 상태 표시가 유지되는가?
- 테스트용 신규 장소 상태가 SO만으로 추가되어 실제 플레이 경로에서 표시/효과/저장/로드됐는가?
- 체크리스트 항목 중 하나라도 FAIL이면 완료로 보고하지 않고 실패 단계와 남은 작업을 보고했는가?

싱글/멀티 정책:
- 싱글플레이에서 혼자 장소 시간대 상태를 발견하고 활용할 수 있어야 한다.
- 시간 흐름, Shared 월드 상태 기반 장소 변화, NPC 스케줄 기반 장소 상태는 모든 클라이언트에서 동일하게 보여야 한다.
- 상태 발견 여부, 상태별 보상 수령 여부, 도감/진로 힌트/퀘스트 결과는 Personal로 저장한다.
- Client 1과 Client 2는 같은 시간대의 도서관 상태를 동일하게 보되, 각자 발견/보상/도감 상태는 분리되어야 한다.
- 멀티플레이 직접 검증이 이번 범위에 포함되면 실제 클라이언트 2개 이상 또는 Host+Client를 띄워 시간 동기화와 Personal 발견 상태 분리를 확인한다.
- 멀티플레이 직접 검증이 범위 밖이면 최종 보고에 후속 NET 테스트 계획을 명시한다.

목표 플레이 흐름:
1. 저장 슬롯 UI로 새 게임 또는 기존 슬롯 로드 후 Town에 진입한다.
2. 플레이어가 실제 이동으로 도서관, 공방, 상점, 광장, 골목 중 하나에 접근한다.
3. 장소 UI 또는 진입 배너에서 현재 시간대 장소 상태를 확인한다.
4. 현재 상태에서 가능한 활동/NPC/단서/상호작용 중 하나를 실제 Prompt/Input/Button 경로로 수행한다.
5. 실제 하루/시간 흐름을 진행해 다른 시간대가 되게 한다.
6. 같은 장소를 다시 실제 이동으로 방문한다.
7. 이전 시간대와 다른 장소 상태, 활동, NPC, 단서, 상호작용을 확인한다.
8. 장소 숙련도/친밀도 또는 월드 상태 조건을 실제 플레이로 만족시켜 추가 상태를 연다.
9. 추가 상태에서 새 활동/NPC/단서/상호작용 중 최소 1개를 실제로 수행한다.
10. 하루 결과 UI에서 오늘 발견한 장소 상태와 새로 열린 활동/단서를 확인한다.
11. 저장 슬롯 UI로 같은 슬롯을 다시 로드한다.
12. 재로드 후 상태 발견 여부, 보상 수령 여부, 미확인 상태 표시가 유지되는지 확인한다.
13. SO만으로 추가한 테스트 장소 상태도 같은 흐름으로 표시/효과/저장/로드한다.

필수 저장 데이터:
- saveSlot
- player identity
- location state id
- discovered state ids
- first discovered day/time
- state reward claimed flags
- last visited state id per location
- today location state summary
- hidden/unknown state hint visibility

필수 EditMode 테스트:
- LOCATION-STATE-EDIT-001: LocationStateDefinition/condition/effect/conflict policy가 Registry 또는 지정 데이터 경로에서 로드된다.
- LOCATION-STATE-EDIT-002: 새 테스트 장소 상태가 C# 코드 수정 없이 SO 추가와 Registry 등록만으로 로드된다.
- LOCATION-STATE-EDIT-003: 시간대 조건이 특정 timeSlotId별 if/switch 없이 장소 상태를 선택한다.
- LOCATION-STATE-EDIT-004: 장소 숙련도/친밀도, 월드 상태, NPC 스케줄, 퀘스트 상태 조건이 전략 배열로 평가된다.
- LOCATION-STATE-EDIT-005: 한 장소가 2개 이상 시간대 상태를 가질 수 있다.
- LOCATION-STATE-EDIT-006: 하나의 장소 상태가 활동/NPC/단서/오브젝트/포탈 효과를 여러 개 제공한다.
- LOCATION-STATE-EDIT-007: 여러 상태가 동시에 조건을 만족할 때 우선순위/병합/대체 정책이 동작한다.
- LOCATION-STATE-EDIT-008: 저장/로드 후 상태 발견 여부와 보상 수령 여부가 복원된다.
- LOCATION-STATE-EDIT-009: UI summary 생성이 매 호출 Registry 전체 순회를 요구하지 않는 구조인지 검증한다.

필수 PlayMode E2E 시나리오:
- LOCATION-STATE-E2E-001: 저장 슬롯 UI로 Town에 진입한다.
```
