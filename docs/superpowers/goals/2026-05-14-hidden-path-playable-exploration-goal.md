# Hidden Path Playable Exploration Goal Prompt

아래 프롬프트를 goal 세션에 그대로 붙여 넣고 진행한다.

```text
ROOTBORN Unity 프로젝트에서 "숨은 길/새 장소/탐험 지점이 데이터와 UI 문구로만 존재하지 않고, 기존 타일셋/프리팹을 사용해 실제 PlayMode에서 보이고, 플레이어가 직접 이동/상호작용으로 발견·입장·조사할 수 있는 최소 플레이 공간"을 설계/구현/검증해줘.

핵심 의도:
- 숨은 길 탐험은 문서, 더미 데이터, 버튼 UI만으로 완료하지 않는다.
- 플레이어가 실제 맵에서 숨은 길 입구를 보고, 키보드 이동으로 접근하고, 상호작용 프롬프트로 조사/입장/탐험해야 한다.
- 새 장소는 거대한 완성 맵일 필요는 없지만, 최소한 플레이 가능한 타일셋/프리팹 기반 공간이어야 한다.
- 숨은 길 발견은 소문/단서/장소 시간대 상태/월드 변화/장소 숙련도와 연결될 수 있어야 한다.
- 싱글플레이에서 혼자 발견부터 탐험 결과까지 완료 가능해야 한다.

헌법 규칙:
- AGENTS.md와 `.claude/rules/*`를 따른다.
- `Assets/**/*.cs`를 외부 디스크 쓰기로 직접 수정하지 않는다. C# 신규/수정은 반드시 Unity MCP `script-update-or-create` 또는 Unity Editor 안전 경로를 사용한다.
- 모든 게임 엔티티는 100% ScriptableObject 데이터 기반이어야 한다.
- hiddenPathId, locationId, portalId, clueId, worldStateId별 `if/switch` 분기, enum 기반 엔티티 분기, 숨은 길별 C# 클래스 생성은 금지한다.
- 숨은 길 조건, 입구 표시, 포탈 이동, 탐험 결과, 도감/진로 힌트/퀘스트/월드 상태 보상은 SO 데이터와 전략 배열로 표현한다.
- 저장/로드 후 숨은 길 개방, 발견, 입장, 탐험 보상 상태가 중복 적용되면 안 된다.
- TDD로 진행한다. 먼저 실패하는 테스트를 만들고 실패를 확인한 뒤 구현한다.
- 성능/최적화 동시 설계 원칙을 따른다.
- 기존 dirty 변경을 되돌리지 않는다.

필수 플레이 공간 요구:
- 숨은 길/새 장소/탐험 지점은 데이터와 UI 문구만으로 완료하지 않는다.
- 기존 Pixelwood Valley 타일셋, 프로젝트 내 기존 타일/스프라이트/프리팹, 또는 현재 사용 중인 맵 구성 방식을 우선 사용한다.
- 최소 1개 이상의 숨은 길 입구 오브젝트를 실제 맵에 배치한다.
- 최소 1개 이상의 이동 목적지 또는 새 탐험 지점을 실제 맵/씬/장소 구조에 배치한다.
- 최소 1개 이상의 탐험 상호작용 지점을 배치한다.
- 플레이어가 키보드 이동으로 입구에 접근하고 실제 프롬프트/Input/Button으로 조사/입장/탐험할 수 있어야 한다.
- 타일셋이 부족하면 임시 프리팹/기존 스프라이트/회색박스 수준으로라도 실제 플레이 가능한 공간을 만들고, 최종 보고에 아트 보강 필요 항목을 남긴다.

권장 데이터 구조:
- `HiddenPathDefinition`
  - 숨은 길 표시명, 설명, 입구 위치/장소, 목적지 장소, 필요 조건, 발견 결과, UI 표시 정책을 정의한다.
- `HiddenPathEntranceDefinition`
  - 입구 오브젝트, 프롬프트 텍스트, Collider/Trigger, 활성 조건, 맵 표시 여부를 정의한다.
- `ExplorationSiteDefinition`
  - 목적지 또는 탐험 지점의 표시명, 설명, 상호작용 포인트, 가능한 활동, 도감/단서/퀘스트 연결을 정의한다.
- `HiddenPathConditionBase[]`
  - 월드 상태, 소문/단서 완료, 장소 숙련도, 시간대 장소 상태, 퀘스트 상태, NPC 반응, 아이템 보유를 일반 조건으로 평가한다.
- `HiddenPathOutcomeBase[]`
  - 새 장소 발견, 도감 항목, 진로 힌트, 후속 퀘스트, 월드 변화 활용 요소, 장소 숙련도 증가, 하루 이벤트 후보를 일반 결과로 처리한다.
- `HiddenPathProgress`
  - saveSlot + player identity 기준으로 발견 여부, 입장 여부, 탐험 완료 여부, 보상 수령 여부, 마지막 방문 날짜를 저장한다.
- `HiddenPathSummaryModel`
  - 장소 UI, 지도 UI, 도감 UI, 월드 로그 UI, 탐험 결과 UI에서 공통으로 사용하는 표시 모델이다.

초기 구현 예시:
- 골목 숨은 길
  - 입구: 골목 구석 낡은 담장 틈 또는 어두운 통로 오브젝트
  - 조건: 골목 바람 소리 단서 완료 또는 숨은 길 개방 WorldStateFlag 활성화
  - 목적지: `골목 안쪽` 또는 `낡은 담장 뒤`
  - 상호작용: `조사하기`, `안쪽으로 들어가기`
  - 결과: 새 장소 발견, 탐험·정보형 진로 힌트, 도감 `골목 안쪽 통로`, 후속 단서 후보
- 도서관 자료실 안쪽
  - 입구: 자료실 뒤편 문/책장 틈
  - 조건: 도서관 자료실 개방 + 도서관 숙련도/시간대 조건
  - 결과: 오래된 기록 단서, 학습형/탐험형 힌트, 도감 확장

UI 요구:
- 장소 진입 배너를 표시한다.
  - 예: `골목 안쪽`
  - 예: `낡은 담장 틈`
- 입구 오브젝트 근처에 실제 상호작용 프롬프트를 표시한다.
  - 예: `조사하기`
  - 예: `안쪽으로 들어가기`
- 탐험 결과 패널을 표시한다.
  - `새 장소 발견`
  - `오래된 흔적 발견`
  - `탐험형 진로 힌트 +1`
  - `도감 항목 발견`
- 도감/월드 로그에는 발견 전 `??? 숨은 길`, 발견 후 실제 이름과 설명을 표시한다.
- 지도/장소 UI에는 발견한 숨은 길 또는 미확인 흔적을 표시한다.
- UI는 특정 hiddenPathId/locationId를 직접 알지 않고 `HiddenPathSummaryModel`을 렌더링한다.
- Modern UI Style2 공통 패널 규약을 따른다.
- 1920x1080 기준에서 장소명, 프롬프트, 결과 텍스트, 버튼 텍스트가 겹치거나 잘리지 않아야 한다.
- UI는 문서 목업만 만들고 끝내면 안 된다. PlayMode에서 실제로 열리고 클릭 가능해야 한다.

확장성 검증:
- 새 숨은 길/탐험 지점은 C# 코드 수정 없이 ScriptableObject 데이터 추가와 Registry 등록만으로 추가 가능해야 한다.
- 테스트용 신규 `HiddenPathDefinition` 또는 `ExplorationSiteDefinition`을 1개 이상 추가하고, 기존 런타임 코드를 수정하지 않은 상태에서 입구 표시, 이동, 상호작용, 결과, 저장/로드가 동작하는지 검증한다.
- 하나의 숨은 길은 여러 조건을 가질 수 있어야 한다.
- 하나의 탐험 지점은 여러 결과/보상/후속 콘텐츠를 열 수 있어야 한다.
- 소문/단서, 장소 시간대 상태, 장소 숙련도, 월드 상태, 퀘스트 체인과 연결 가능해야 한다.
- 같은 탐험 결과를 반복 확인해도 중복 보상, 중복 도감 발견, 중복 퀘스트 해금, 중복 진로 힌트가 발생하지 않아야 한다.
- 최종 보고에는 "숨은 길 탐험 확장성 검증 체크리스트"를 포함하고, SO만으로 추가한 테스트 숨은 길/탐험 지점의 실제 플레이 검증 결과를 기록한다.

최우선 실제 플레이 검증 원칙:
- 이 goal은 실제 유저가 플레이하듯 검증하지 않으면 완료로 인정하지 않는다.
- 최소 1개 이상의 PlayMode E2E는 저장 슬롯 UI에서 시작해 실제 키보드 이동, 실제 맵 입구 접근, 실제 프롬프트/Input/Button, 실제 포탈/장소 이동, 실제 탐험 상호작용, 결과 UI 확인, 저장/로드 재진입을 모두 거쳐야 한다.
- 테스트에서 HiddenPathProgress, WorldStateProgress, DiscoveryClueProgress, SaveData 상태를 직접 세팅해서 성공 처리하면 실패다.
- 플레이어 Transform 직접 이동, 내부 메서드 직접 호출, 씬 강제 로드, 저장 데이터 직접 주입, UI 없이 도메인 API 직접 호출로 실제 플레이 경로를 대체하면 완료로 보고하지 않는다.
- 최종 보고 전에 "실제 플레이 방식 상호작용 검증 체크리스트"를 반드시 작성하고, 각 항목을 PASS/FAIL로 표시한다.

실제 플레이 방식 상호작용 검증 체크리스트:
- 저장 슬롯 UI에서 새 게임 또는 기존 슬롯을 실제 UI 경로로 시작했는가?
- 플레이어 이동이 Transform 직접 세팅이 아니라 키보드/입력 시스템 경로로 수행됐는가?
- 숨은 길 입구가 실제 맵에 보이는 오브젝트/타일/프리팹으로 배치됐는가?
- 플레이어가 실제 이동으로 입구에 접근했는가?
- 실제 Prompt/Input/Button 경로로 조사/입장/탐험을 수행했는가?
- 실제 포탈/장소 이동 또는 탐험 지점 진입이 발생했는가?
- 새 장소명/프롬프트/탐험 결과 UI가 PlayMode에서 표시됐는가?
- 탐험 결과가 도감, 진로 힌트, 후속 퀘스트, 월드 변화 활용 요소 중 최소 1개 이상으로 이어졌는가?
- 저장 슬롯 UI 재진입 후 같은 슬롯을 로드했을 때 숨은 길 발견/입장/탐험/보상 상태가 유지되는가?
- 같은 탐험 결과를 반복 확인해도 중복 보상/중복 발견/중복 해금이 발생하지 않는가?
- 테스트용 신규 숨은 길 또는 탐험 지점이 SO만으로 추가되어 실제 플레이 경로에서 표시/이동/상호작용/저장/로드됐는가?
- 체크리스트 항목 중 하나라도 FAIL이면 완료로 보고하지 않고 실패 단계와 남은 작업을 보고했는가?

싱글/멀티 정책:
- 싱글플레이에서 혼자 숨은 길 발견/입장/탐험 완료가 가능해야 한다.
- Shared 월드 상태로 열린 숨은 길 입구/포탈/장소는 모든 클라이언트가 볼 수 있다.
- 발견 여부, 탐험 완료 여부, 도감 발견, 진로 힌트, 보상 수령 여부는 기본 Personal이다.
- Client 1이 숨은 길 입구를 열면 Client 2도 입구를 볼 수 있지만, Client 2의 탐험 보상/도감/진로 힌트는 별도로 처리한다.
- 멀티플레이 직접 검증이 이번 범위에 포함되면 실제 클라이언트 2개 이상 또는 Host+Client를 띄워 Shared 입구와 Personal 탐험 상태 분리를 확인한다.
- 멀티플레이 직접 검증이 범위 밖이면 최종 보고에 후속 NET 테스트 계획을 명시한다.

목표 플레이 흐름:
1. 저장 슬롯 UI로 새 게임 또는 기존 슬롯 로드 후 Town에 진입한다.
2. 실제 플레이로 숨은 길 조건을 만족한다.
   - 예: 골목 바람 소리 단서 완료
   - 예: 숨은 길 개방 WorldStateFlag 활성화
   - 예: 장소 시간대 상태/장소 숙련도 조건 만족
3. 플레이어가 실제 이동으로 숨은 길 입구가 있는 장소에 접근한다.
4. 실제 맵에 배치된 입구 오브젝트/타일/프리팹을 확인한다.
5. 실제 프롬프트/Input/Button으로 `조사하기` 또는 `안쪽으로 들어가기`를 실행한다.
6. 새 장소 또는 탐험 지점으로 이동한다.
7. 장소 진입 배너와 장소명 UI를 확인한다.
8. 탐험 상호작용 지점에서 실제 Input/Button으로 조사한다.
9. 탐험 결과 UI에서 새 장소 발견, 단서/도감/진로 힌트/후속 퀘스트 중 최소 1개 결과를 확인한다.
10. 도감/월드 로그/지도 UI에서 발견 상태가 반영됐는지 확인한다.
11. 저장 슬롯 UI로 같은 슬롯을 다시 로드한다.
12. 재로드 후 숨은 길 발견/입장/탐험/보상 상태가 유지되는지 확인한다.
13. 같은 탐험 결과를 반복 확인해 중복 보상/중복 해금/중복 발견이 발생하지 않는지 확인한다.
14. SO만으로 추가한 테스트 숨은 길/탐험 지점도 같은 흐름으로 표시/이동/상호작용/저장/로드한다.

필수 저장 데이터:
- saveSlot
- player identity
- hidden path id
- entrance discovered flag
- path entered flag
- exploration completed flag
- first discovered day/time
- last entered day/time
- reward claimed flags
- discovered encyclopedia entry ids
- career hint grant history
- follow-up quest ids
- today hidden path summary

필수 EditMode 테스트:
- HIDDEN-PATH-EDIT-001: HiddenPathDefinition/Entrance/ExplorationSite/Condition/Outcome 전략이 Registry 또는 지정 데이터 경로에서 로드된다.
- HIDDEN-PATH-EDIT-002: 새 테스트 숨은 길 또는 탐험 지점이 C# 코드 수정 없이 SO 추가와 Registry 등록만으로 로드된다.
- HIDDEN-PATH-EDIT-003: 숨은 길 활성 조건은 hiddenPathId/locationId별 if/switch 없이 전략 배열로 평가된다.
- HIDDEN-PATH-EDIT-004: 숨은 길 조건이 소문/단서, 장소 시간대 상태, 장소 숙련도, 월드 상태, 퀘스트 체인을 조합할 수 있다.
```
