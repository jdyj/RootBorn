# Goal: 닫힌 피드백 루프 검증 및 보강

ROOTBORN Unity 프로젝트에서 NPC 대화, 퀘스트, 특성/성향 성장, 스킬/직업 진행이 실제 플레이 루프로 닫혀 있는지 검증하고, 비어 있는 구간은 데이터 기반으로 보강한다.

## 절대 원칙

- 모든 신규/수정 게임 엔티티는 ScriptableObject 데이터 기반으로 구성한다.
- `if (questId == "...")`, `if (careerId == "...")`, `switch(activityId)` 같은 엔티티 ID 분기 금지.
- C# 스크립트는 직접 디스크 쓰기 금지. Unity MCP `script-update-or-create`를 사용한다.
- TDD 필수: 실패 테스트를 먼저 추가하고, 실패를 확인한 뒤 구현한다.
- 직접 캐릭터를 움직이고, 상호작용 거리 프롬프트와 E키 상호작용을 통해 루프를 검증한다.

## 루프 1: NPC 대화 -> 퀘스트 -> 특성/성향 성장 -> NPC 대화

다음 흐름을 실제 게임 실행 기준으로 검증한다.

1. 게임 실행
2. 게임 로드
3. 캐릭터 직접 이동
4. NPC 근처 접근
5. 상호작용 가능 프롬프트 확인
6. E키로 NPC 대화
7. 퀘스트 수주
8. 퀘스트 목표 수행
9. 보상/완료 처리
10. 특성/성향 상승 확인
11. 다시 NPC와 대화
12. 다음 퀘스트 또는 다음 상태 대화로 이어지는지 확인

### 루프 1 요구사항

- 4개의 직업 루트가 모두 이 루프 안에서 테스트 가능해야 한다.
- 각 직업 루트마다 최소 1개 이상의 NPC 대화/퀘스트/특성 성장 연결이 있어야 한다.
- 퀘스트 완료 후 특성/성향이 오르지 않는 구간이 있으면, 누락으로 간주하고 기획/데이터를 보강한다.
- 필요한 경우 신규 `QuestDefinition`, `DialogueDefinition`, `DialogueChoiceDefinition`, `QuestObjective`, `QuestReward`, `QuestCompletionEffect` SO를 추가한다.
- 보상 지급은 기존 인벤토리/보상 트랜잭션 원칙을 지킨다.
- PlayMode 테스트는 캐릭터 이동, NPC 접근, 프롬프트 표시, E키 상호작용, 대화창 열림, 퀘스트 수락, 목표 완료, 특성 상승까지 검증한다.

## 루프 2: 행동 -> 특성/성향 성장 -> 스킬 학습 -> 반복 행동

다음 흐름을 실제 게임 실행 기준으로 검증한다.

1. 게임 실행
2. 게임 로드
3. 캐릭터 직접 이동
4. 특성/성향이 오르는 행동 오브젝트 근처 접근
5. 상호작용 가능 프롬프트 확인
6. E키로 행동 실행
7. 특성/성향 상승 확인
8. 조건 충족 시 스킬 학습 또는 스킬 진행 확인
9. 다시 특성/성향 행동 수행
10. 성장/스킬/직업 힌트가 반복적으로 이어지는지 확인

### 루프 2 요구사항

- 4개의 직업 루트가 모두 행동 기반 성장 루프 안에서 테스트 가능해야 한다.
- 각 직업 루트마다 최소 1개 이상의 특성/성향 행동과 스킬 성장 연결이 있어야 한다.
- 특성/성향이 올라야 하는 행동인데 실제로 오르지 않으면 누락으로 간주하고 기획/데이터를 보강한다.
- 필요한 경우 신규 `LifeActivityDefinition`, `LifeChoiceDefinition`, `TraitDefinition`, `SkillDefinition`, `CareerDefinition`, `CareerPracticeDefinition`, Activity Effect/Requirement SO를 추가한다.
- 행동 실행은 데이터/전략 배열 기반으로 처리하고, 직업별 C# 분기는 만들지 않는다.
- PlayMode 테스트는 캐릭터 이동, 행동 오브젝트 접근, 프롬프트 표시, E키 상호작용, 특성/성향 상승, 스킬 진행, 직업 힌트/루트 연결을 검증한다.

## 4개 직업 검증 기준

다음 4개 직업 루트가 모두 루프 1과 루프 2에서 검증 가능해야 한다.

- chef
- interior
- soldier
- emergency-care

각 직업에 대해 확인할 것:

- NPC 대화 또는 퀘스트로 진입 가능한가
- 행동/활동으로 관련 특성 또는 성향이 오르는가
- 관련 스킬 또는 직업 힌트가 열리는가
- 반복 수행 시 상태가 누적 또는 진행되는가
- 저장/로드 후 진행 상태가 유지되는가

## 테스트 요구사항

다음 테스트를 추가하거나 보강한다.

- PlayMode: 게임 로드 후 Player가 실제 이동 가능한지
- PlayMode: NPC 근처에서 프롬프트가 뜨고 E키로 대화가 열리는지
- PlayMode: 퀘스트 수락 후 목표 수행으로 특성/성향이 상승하는지
- PlayMode: 4개 직업 루트 각각에서 퀘스트 기반 성장 루프가 닫히는지
- PlayMode: 행동 오브젝트 근처에서 프롬프트가 뜨고 E키로 행동이 실행되는지
- PlayMode: 4개 직업 루트 각각에서 행동 기반 성장/스킬 루프가 닫히는지
- EditMode: SO 데이터가 Registry에 등록되어 있고 null 참조가 없는지
- EditMode: 엔티티 ID 분기 없이 데이터/전략 기반으로 구성되어 있는지

## 완료 조건

- 루프 1과 루프 2가 실제 캐릭터 이동 및 E키 상호작용으로 모두 검증된다.
- 4개 직업 루트가 모두 퀘스트 기반 루프와 행동 기반 루프에서 테스트된다.
- 특성/성향이 오르지 않는 비어 있는 구간은 데이터 또는 기획으로 보강된다.
- 신규/수정 데이터는 `Assets/Data/...`와 `GameDataRegistry.asset`에 등록된다.
- 관련 PlayMode/EditMode 테스트가 통과한다.
- `Scripts/ci/check-no-entity-id-branching.sh`가 통과한다.
- 변경 요약과 테스트 결과를 보고한다.
