# Part Time Work Growth Goal Prompt

아래 프롬프트를 goal 세션에 그대로 붙여 넣고 진행한다.

```text
ROOTBORN Unity 프로젝트에서 "학생이 학교 수업 대신 Town의 상점/카페/마을 시설에서 짧은 알바 또는 일손 돕기를 실제 이동/상호작용으로 수행하면 돈·책임감·사교성·피로·관계·진로 힌트가 변화하고, 하루 결과 UI와 저장/로드 후 상태에 반영되는 알바 성장 루프"를 설계/구현/검증해줘.

핵심 의도:
- 학교 밖에서도 경제와 진로로 이어지는 성장 경로를 제공한다.
- 알바는 돈 보상뿐 아니라 관계, 평판, 책임감, 피로, 진로 힌트를 움직이는 생활 선택이어야 한다.
- 플레이어가 하루 시간을 어디에 쓸지 고민하게 만든다.

최우선 검증 원칙:
- 실제 플레이 방식으로 검증하지 않으면 완료로 인정하지 않는다.
- 최소 1개 이상의 PlayMode E2E는 저장 슬롯 UI, 실제 이동, 알바 장소 접근, 실제 상호작용 입력, 알바 수행, 보상/비용 반영, 하루 종료, 결과 UI, 저장/로드를 거쳐야 한다.
- 학교 수업 없이 알바 루트만으로 돈 또는 특성/관계/진로 힌트가 진행되는 것을 증명해야 한다.
- 내부 API 직접 호출이나 상태 강제 세팅으로 알바 성공을 대체하면 실패다.

절대 규칙:
- AGENTS.md와 `.claude/rules/*`를 따른다.
- `Assets/**/*.cs`는 디스크 직접 쓰기 금지. C# 신규/수정은 반드시 Unity MCP `script-update-or-create` 또는 Unity Editor 안전 경로를 사용한다.
- 모든 게임 엔티티는 100% ScriptableObject 데이터 기반이어야 한다.
- jobId, workplaceId, npcId, itemId, traitId, relationshipId별 `if/switch` 분기, enum 기반 엔티티 분기, 엔티티별 C# 클래스 생성은 금지한다.
- 알바 정의, 근무 조건, 비용, 보상, 관계/평판/진로 힌트 변화는 SO 데이터와 전략 배열로 표현한다.
- 보상 지급은 인벤토리/재화 수용 가능 여부와 중복 수령 여부를 검증하고 원자적으로 처리한다.
- TDD로 진행한다. 먼저 실패하는 테스트를 만들고 실패를 확인한 뒤 구현한다.
- 기존 dirty 변경 되돌리기 금지.

권장 구조:
- `PartTimeWorkDefinition`
  - 근무 장소, 시간대, 필요 조건, 비용, 보상, 결과 전략 배열을 정의한다.
- `WorkplaceDefinition`
  - 상점/카페/시설 같은 장소와 NPC, 가능 알바 목록을 데이터로 정의한다.
- `WorkRequirementBase[]`
  - 시간대, 컨디션, 관계, 튜토리얼 단계, 스킬 조건을 평가한다.
- `WorkOutcomeBase[]`
  - 돈, 아이템, 특성/성향, 관계, 피로, 진로 힌트, 퀘스트 이벤트를 적용한다.
- `PartTimeWorkInteractor`
  - 월드 알바 지점 또는 NPC를 실제 상호작용 가능하게 한다.

목표 플레이 흐름:
1. 저장 슬롯 UI로 Town에 진입한다.
2. 플레이어가 학교 수업 없이 상점/카페/시설 알바 지점으로 실제 이동한다.
3. 실제 상호작용 입력과 UI 버튼으로 알바를 시작한다.
4. 알바 조건이 충족되면 서버/도메인 권한 규칙에 따라 결과가 확정된다.
5. 돈/아이템 보상 또는 특성/관계/진로 힌트 변화가 적용된다.
6. 피로/컨디션 비용이 적용된다.
7. UI 또는 HUD에서 돈/인벤토리/관계/컨디션 변화가 확인된다.
8. 플레이어가 하루 종료 지점으로 실제 이동해 하루를 종료한다.
9. 하루 결과 UI에 알바, 보상, 비용, 성장 결과가 표시된다.
10. 저장 슬롯 UI로 같은 슬롯을 다시 로드해도 알바 결과가 유지된다.
11. 같은 알바 보상이 저장/로드 후 중복 지급되지 않는다.

멀티플레이 확장 고려:
- 알바 결과는 개인 상태로 처리한다.
- 같은 근무 슬롯을 여러 플레이어가 동시에 사용할 수 있는지, 공유 소모되는지 데이터로 정의한다.
- 멀티플레이에서는 서버 권한으로 알바 요청/보상/비용을 확정할 수 있어야 한다.

필수 테스트:
- WORK-EDIT-001: PartTimeWorkDefinition/WorkplaceDefinition이 Registry 또는 지정 데이터 경로에서 로드된다.
- WORK-EDIT-002: 알바 요구 조건과 결과 전략이 엔티티 ID별 분기 없이 실행된다.
- WORK-EDIT-003: 보상 지급 전 수용 가능 여부와 중복 수령 여부를 검증한다.
- WORK-EDIT-004: 알바 결과가 돈/아이템/특성/관계/컨디션/진로 힌트 중 하나 이상을 변경한다.
- WORK-EDIT-005: 저장/로드 후 같은 알바 보상이 중복 지급되지 않는다.
- WORK-E2E-001: 저장 슬롯 UI로 Town에 진입한다.
- WORK-E2E-002: 학교 수업 없이 실제 이동으로 알바 장소에 접근한다.
- WORK-E2E-003: 실제 상호작용 입력/UI 버튼으로 알바를 수행한다.
- WORK-E2E-004: 돈/인벤토리/특성/관계/컨디션 변화가 UI와 도메인 상태에 함께 반영된다.
- WORK-E2E-005: 하루 결과 UI에 알바 보상과 비용이 표시된다.
- WORK-E2E-006: 저장/로드 후 알바 결과가 유지되고 중복 지급되지 않는다.

완료 조건:
- 학교 수업 없이 알바만으로 돈 또는 특성/관계/진로 힌트 진행이 가능하다.
- 알바는 보상과 컨디션 비용을 함께 가진다.
- 보상/인벤토리 트랜잭션 원칙을 위반하지 않는다.
- 실제 플레이 E2E가 알바 루트를 검증한다.
- 알바 데이터는 SO와 전략 배열 기반이며 엔티티 ID별 분기가 없다.
- 관련 EditMode/PlayMode 테스트가 통과한다.
- `Scripts/ci/check-no-entity-id-branching.sh`가 통과한다.
- 최종 보고에는 수정 파일, 생성/수정한 SO 에셋, 실행한 테스트, 실제 플레이 검증 흐름, 통과/실패 결과, 멀티플레이 확장 리스크를 포함한다.
```
