# Exploration Interaction Choice Goal Prompt

아래 프롬프트를 goal 세션에 그대로 붙여 넣고 진행한다.

```text
ROOTBORN Unity 프로젝트에서 "숨은 길/새 장소 안의 조사 지점에서 플레이어가 실제 이동과 상호작용으로 조사 방식을 선택하고, 선택에 따라 단서/도감/진로 힌트/아이템/피로도/후속 퀘스트가 달라지는 탐험 행동 미니 루프"를 설계/구현/검증해줘.

핵심 의도:
- 숨은 길/새 장소는 발견 1회로 끝나는 맵이 아니라, 안에서 여러 조사 지점을 직접 탐색하는 공간이어야 한다.
- 플레이어는 조사 지점에 직접 걸어가서 상호작용하고, 조사 방식을 선택해야 한다.
- 같은 조사 지점이라도 선택 방식에 따라 결과가 달라져야 한다.
- 결과는 단서, 도감, 진로 힌트, 아이템, 피로도/상태 변화, 후속 퀘스트, 장소 숙련도와 연결될 수 있어야 한다.
- 싱글플레이에서 혼자 모든 탐험 조사 루프를 완료할 수 있어야 한다.
- 새 조사 지점과 조사 선택지는 C# 코드 수정 없이 ScriptableObject 데이터 추가와 Registry 등록만으로 추가 가능해야 한다.

헌법 규칙:
- AGENTS.md와 `.claude/rules/*`를 따른다.
- `Assets/**/*.cs`를 외부 디스크 쓰기로 직접 수정하지 않는다. C# 신규/수정은 반드시 Unity MCP `script-update-or-create` 또는 Unity Editor 안전 경로를 사용한다.
- 모든 게임 엔티티는 100% ScriptableObject 데이터 기반이어야 한다.
- explorationId, choiceId, siteId, hiddenPathId, itemId, clueId, questId별 `if/switch` 분기, enum 기반 엔티티 분기, 조사 지점별 C# 클래스 생성은 금지한다.
- 조사 지점, 조사 선택지, 조건, 결과, 반복/소모/위험 정책은 SO 데이터와 전략 배열로 표현한다.
- 아이템/도감/진로 힌트/퀘스트/피로도/상태/장소 숙련도 결과는 저장/로드 후 중복 적용되면 안 된다.
- TDD로 진행한다. 먼저 실패하는 테스트를 만들고 실패를 확인한 뒤 구현한다.
- 성능/최적화 동시 설계 원칙을 따른다.
- 기존 dirty 변경을 되돌리지 않는다.

권장 데이터 구조:
- `ExplorationInteractionDefinition`
  - 조사 지점 표시명, 설명, 관련 장소/숨은 길/오브젝트, 프롬프트 텍스트, 반복 가능 여부, UI 표시 정책을 정의한다.
- `ExplorationChoiceDefinition`
  - 조사 방식 표시명, 설명, 필요 조건, 결과, 소모/위험/반복 정책을 정의한다.
- `ExplorationConditionBase[]`
  - 도구/아이템 보유, 장소 숙련도, 시간대, 단서 상태, 관심 진로, 월드 상태, 퀘스트 상태, 이전 조사 여부를 일반 조건으로 평가한다.
- `ExplorationOutcomeBase[]`
  - 도감 발견, 단서 획득, 진로 힌트, 아이템 획득/소모, 피로도/상태 변화, 후속 퀘스트, 장소 숙련도 증가, 월드 상태 변화를 일반 결과로 처리한다.
- `ExplorationRiskPolicyDefinition`
  - 피로도 증가, 상태 이상, 실패 가능성, 아이템 소모, 하루 제한, 쿨다운을 데이터로 정의한다.
- `ExplorationProgress`
  - saveSlot + player identity 기준으로 조사 지점별 발견 여부, 선택한 방식, 완료 여부, 보상 수령 여부, 반복 횟수, 마지막 조사 날짜를 저장한다.
- `ExplorationSummaryModel`
  - 조사 프롬프트 UI, 조사 선택 UI, 결과 UI, 도감/월드 로그 UI에서 공통으로 사용하는 표시 모델이다.

초기 조사 지점 예시:
- 골목 안쪽 `낡은 상자`
  - 선택지:
    - `조심히 열기`: 작은 아이템, 도감 흔적, 피로도 소량
    - `힘으로 열기`: 빠른 획득, 피로도 증가, 실용/기술형 힌트 후보
    - `기록으로 남기기`: 탐험형 진로 힌트, 도감 기록
    - `그만두기`: 변화 없음
- 골목 안쪽 `벽의 흔적`
  - 선택지:
    - `자세히 보기`: 오래된 표식 단서
    - `지도에 표시`: 지도 기록, 후속 탐험 후보
    - `무시하기`: 변화 없음
- 골목 안쪽 `막힌 문`
  - 선택지:
    - `도구로 열기`: 도구/공방 숙련도 조건 필요, 새 포탈 또는 후속 퀘스트
    - `살펴보기`: 잠긴 문 단서
    - `돌아가기`: 변화 없음
- 도서관 자료실 `오래된 책장`
  - 선택지:
    - `조심히 열람`: 학습형 힌트, 도감 확장
    - `빠르게 훑기`: 단서 일부, 피로도 적음
    - `사서에게 물어보기 후보 생성`: NPC 해석 경로 추가

UI 요구:
- 조사 지점 근처에 실제 상호작용 프롬프트 `조사하기`를 표시한다.
- 조사 선택 UI에는 가능한 선택지와 잠긴 선택지를 표시한다.
- 잠긴 선택지는 `???` 또는 부족 조건 일부를 보여준다.
- 선택지에는 예상되는 소모/위험을 너무 노골적인 정답표가 아니라 짧은 힌트로 표시한다.
- 결과 UI에는 발견한 것, 소모/위험, 열린 단서/도감/퀘스트/진로 힌트를 표시한다.
- 도감/월드 로그에는 조사 완료 여부와 발견 결과가 반영된다.
- UI는 특정 explorationId/choiceId를 직접 알지 않고 `ExplorationSummaryModel`을 렌더링한다.
- Modern UI Style2 공통 패널 규약을 따른다.
- 1920x1080 기준에서 조사명, 선택지, 조건, 결과, 버튼 텍스트가 겹치거나 잘리지 않아야 한다.
- UI는 문서 목업만 만들고 끝내면 안 된다. PlayMode에서 실제로 열리고 클릭 가능해야 한다.

확장성 검증:
- 새 조사 지점과 선택지는 C# 코드 수정 없이 ScriptableObject 데이터 추가와 Registry 등록만으로 추가 가능해야 한다.
- 테스트용 신규 `ExplorationInteractionDefinition` 1개와 선택지 3개 이상을 SO만으로 추가한다.
- 기존 런타임 코드를 수정하지 않은 상태에서 조사 지점 표시, 선택 UI, 결과, 저장/로드가 동작하는지 검증한다.
- 하나의 조사 지점은 여러 선택지를 가질 수 있어야 한다.
- 하나의 선택지는 여러 조건과 여러 결과를 가질 수 있어야 한다.
- 같은 조사 지점의 선택 결과가 도감/단서/진로 힌트/아이템/피로도/후속 퀘스트 중 여러 시스템에 연결될 수 있어야 한다.
- 반복 가능/1회성/쿨다운/아이템 소모/위험 정책을 데이터로 정의할 수 있어야 한다.
- 같은 조사 결과를 반복 확인해도 중복 보상, 중복 도감 발견, 중복 퀘스트 해금, 중복 진로 힌트가 발생하지 않아야 한다.
- 최종 보고에는 "탐험 조사 선택 확장성 검증 체크리스트"를 포함하고, SO만으로 추가한 테스트 조사 지점/선택지의 실제 플레이 검증 결과를 기록한다.

최우선 실제 플레이 검증 원칙:
- 이 goal은 실제 유저가 플레이하듯 검증하지 않으면 완료로 인정하지 않는다.
- 최소 1개 이상의 PlayMode E2E는 저장 슬롯 UI에서 시작해 실제 키보드 이동, 실제 숨은 길/새 장소 진입, 실제 조사 지점 접근, 실제 프롬프트/Input/Button, 실제 조사 선택 UI, 결과 UI 확인, 저장/로드 재진입을 모두 거쳐야 한다.
- 테스트에서 ExplorationProgress, HiddenPathProgress, DiscoveryClueProgress, Inventory, SaveData 상태를 직접 세팅해서 성공 처리하면 실패다.
- 플레이어 Transform 직접 이동, 내부 메서드 직접 호출, 씬 강제 로드, 저장 데이터 직접 주입, UI 없이 도메인 API 직접 호출로 실제 플레이 경로를 대체하면 완료로 보고하지 않는다.
- 최종 보고 전에 "실제 플레이 방식 상호작용 검증 체크리스트"를 반드시 작성하고, 각 항목을 PASS/FAIL로 표시한다.

실제 플레이 방식 상호작용 검증 체크리스트:
- 저장 슬롯 UI에서 새 게임 또는 기존 슬롯을 실제 UI 경로로 시작했는가?
- 플레이어 이동이 Transform 직접 세팅이 아니라 키보드/입력 시스템 경로로 수행됐는가?
- 플레이어가 실제 숨은 길/새 장소에 입장했는가?
- 조사 지점이 실제 맵에 보이는 오브젝트/타일/프리팹으로 배치됐는가?
- 플레이어가 실제 이동으로 조사 지점에 접근했는가?
- 실제 Prompt/Input/Button 경로로 조사 선택 UI를 열었는가?
- 2개 이상의 선택지가 표시되고, 조건 미충족 선택지는 잠김/힌트 상태로 표시됐는가?
- 플레이어가 실제 UI 버튼으로 선택지를 선택했는가?
- 선택 결과가 단서/도감/진로 힌트/아이템/피로도/후속 퀘스트 중 최소 2개 이상으로 이어졌는가?
- 저장 슬롯 UI 재진입 후 같은 슬롯을 로드했을 때 조사 완료 여부, 선택한 방식, 보상 수령 여부가 유지되는가?
- 같은 조사 결과를 반복 확인해도 중복 보상/중복 발견/중복 해금이 발생하지 않는가?
- 테스트용 신규 조사 지점/선택지가 SO만으로 추가되어 실제 플레이 경로에서 표시/선택/결과/저장/로드됐는가?
- 체크리스트 항목 중 하나라도 FAIL이면 완료로 보고하지 않고 실패 단계와 남은 작업을 보고했는가?

싱글/멀티 정책:
- 싱글플레이에서 혼자 탐험 조사 루프를 완료할 수 있어야 한다.
- 조사 지점 오브젝트는 Shared로 보일 수 있다.
- 각 플레이어의 조사 완료 여부, 선택 결과, 보상/도감/진로 힌트/피로도/퀘스트 상태는 Personal이다.
- Client 1이 조사했다고 해서 Client 2의 보상이 사라지거나 완료 처리되면 안 된다.
- 단, 조사 결과가 Shared 월드 상태를 활성화하는 경우 서버 권한으로 모든 클라이언트에 반영 가능하다.
- 멀티플레이 직접 검증이 이번 범위에 포함되면 실제 클라이언트 2개 이상 또는 Host+Client를 띄워 Shared 조사 지점과 Personal 조사 결과 분리를 확인한다.
- 멀티플레이 직접 검증이 범위 밖이면 최종 보고에 후속 NET 테스트 계획을 명시한다.

목표 플레이 흐름:
1. 저장 슬롯 UI로 새 게임 또는 기존 슬롯 로드 후 Town에 진입한다.
2. 실제 플레이로 숨은 길 또는 새 장소에 입장한다.
3. 플레이어가 실제 이동으로 조사 지점에 접근한다.
4. 실제 맵에 배치된 조사 지점 오브젝트/타일/프리팹과 프롬프트를 확인한다.
5. 실제 Prompt/Input/Button으로 조사 선택 UI를 연다.
6. 2개 이상의 선택지와 잠긴 선택지/조건 힌트를 확인한다.
7. 플레이어가 실제 UI 버튼으로 선택지를 선택한다.
8. 결과 UI에서 발견, 보상, 소모/위험, 열린 콘텐츠를 확인한다.
9. 도감/월드 로그/퀘스트/진로 힌트/인벤토리/상태 UI 중 관련 결과를 확인한다.
10. 저장 슬롯 UI로 같은 슬롯을 다시 로드한다.
11. 재로드 후 조사 완료 여부, 선택한 방식, 보상 수령 여부가 유지되는지 확인한다.
12. 같은 조사 결과를 반복 확인해 중복 보상/중복 해금/중복 발견이 발생하지 않는지 확인한다.
13. SO만으로 추가한 테스트 조사 지점/선택지도 같은 흐름으로 표시/선택/결과/저장/로드한다.

- selected choice ids
- completed interaction ids
- repeat count
- first completed day/time
- last completed day/time
- reward claimed flags
- item grant/spend history
- discovered clue ids
- discovered encyclopedia entry ids
- career hint grant history
- follow-up quest ids
- fatigue/status outcome history
- today exploration summary

필수 EditMode 테스트:
- EXPLORATION-CHOICE-EDIT-001: ExplorationInteractionDefinition/Choice/Condition/Outcome/RiskPolicy 전략이 Registry 또는 지정 데이터 경로에서 로드된다.
- EXPLORATION-CHOICE-EDIT-002: 새 테스트 조사 지점과 선택지 3개 이상이 C# 코드 수정 없이 SO 추가와 Registry 등록만으로 로드된다.
- EXPLORATION-CHOICE-EDIT-003: 선택 조건은 explorationId/choiceId/siteId별 if/switch 없이 전략 배열로 평가된다.
- EXPLORATION-CHOICE-EDIT-004: 하나의 조사 지점이 3개 이상 선택지를 제공한다.
- EXPLORATION-CHOICE-EDIT-005: 선택 결과는 도감/단서/진로 힌트/아이템/피로도/후속 퀘스트를 전략 배열로 적용한다.
- EXPLORATION-CHOICE-EDIT-006: 반복 가능/1회성/쿨다운/아이템 소모/위험 정책이 데이터 기반으로 동작한다.
- EXPLORATION-CHOICE-EDIT-007: 저장/로드 후 조사 완료 여부, 선택한 방식, 보상 수령 여부가 복원된다.
- EXPLORATION-CHOICE-EDIT-008: 같은 조사 결과를 반복 적용해도 중복 보상/중복 도감/중복 퀘스트/중복 진로 힌트가 발생하지 않는다.
- EXPLORATION-CHOICE-EDIT-009: UI summary 생성이 매 호출 Registry 전체 순회를 요구하지 않는 구조인지 검증한다.
```
