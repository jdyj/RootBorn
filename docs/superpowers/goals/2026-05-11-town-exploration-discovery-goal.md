# Town Exploration Discovery Goal Prompt

아래 프롬프트를 goal 세션에 그대로 붙여 넣고 진행한다.

```text
ROOTBORN Unity 프로젝트에서 "학생이 학교 수업을 듣지 않고 Town 곳곳을 실제 이동으로 탐험하며 장소·지식·작은 이벤트를 발견하고, 발견 결과가 특성·성향·스킬·진로 힌트·관계·퀘스트로 이어지는 탐험/발견 성장 루프"를 설계/구현/검증해줘.

핵심 의도:
- 오픈월드식 자유 경로 성장 원칙을 공간 탐험으로 체감하게 한다.
- 플레이어가 Town을 돌아다니는 것 자체가 의미 있는 성장과 정보 해금으로 이어져야 한다.
- 탐험은 학교 수업, NPC 퀘스트, 독학, 알바와 연결되는 발견 기반 진입점이어야 한다.

최우선 검증 원칙:
- 실제 플레이 방식으로 검증하지 않으면 완료로 인정하지 않는다.
- 최소 1개 이상의 PlayMode E2E는 저장 슬롯 UI, 실제 키보드 이동, 발견 지점 접근, 실제 트리거/상호작용, 발견 UI/로그, 하루 종료, 결과 UI, 저장/로드를 거쳐야 한다.
- 발견 상태, 지식 해금, 진로 힌트, 퀘스트 시작을 테스트에서 직접 세팅해서 통과시키면 실패다.
- Transform 직접 이동이나 씬 강제 로드로 탐험을 대체하면 완료로 보고하지 않는다.

절대 규칙:
- AGENTS.md와 `.claude/rules/*`를 따른다.
- `Assets/**/*.cs`는 디스크 직접 쓰기 금지. C# 신규/수정은 반드시 Unity MCP `script-update-or-create` 또는 Unity Editor 안전 경로를 사용한다.
- 모든 게임 엔티티는 100% ScriptableObject 데이터 기반이어야 한다.
- discoveryId, locationId, knowledgeId, questId, careerId별 `if/switch` 분기, enum 기반 엔티티 분기, 엔티티별 C# 클래스 생성은 금지한다.
- 발견 지점, 발견 조건, 발견 결과, 지식/진로/퀘스트 해금은 SO 데이터와 전략 배열로 표현한다.
- TDD로 진행한다. 먼저 실패하는 테스트를 만들고 실패를 확인한 뒤 구현한다.
- 기존 dirty 변경 되돌리기 금지.

권장 구조:
- `DiscoveryDefinition`
  - 발견 지점의 표시명, 설명, 위치/범위, 조건, 결과 전략 배열을 정의한다.
- `LocationDefinition`
  - Town 장소와 소속 발견 지점/활동/NPC/스케줄을 정의한다.
- `DiscoveryRequirementBase[]`
  - 시간대, 튜토리얼 단계, 관계, 컨디션, 퀘스트 상태, 이전 발견 여부를 평가한다.
- `DiscoveryOutcomeBase[]`
  - 지식 해금, 진로 힌트, 특성/성향/스킬 변화, 퀘스트 시작, 관계 변화, 인벤토리 보상을 적용한다.
- `DiscoveryPointInteractor`
  - 콜라이더/프롬프트/상호작용으로 발견을 실제 플레이 경로에 연결한다.

목표 플레이 흐름:
1. 저장 슬롯 UI로 Town에 진입한다.
2. 플레이어가 학교 수업 없이 Town의 미발견 장소 또는 발견 지점으로 실제 이동한다.
3. 발견 지점 근처에서 실제 Trigger/Prompt 또는 상호작용 입력이 발생한다.
4. 발견 UI, 로그, HUD 또는 QuestLog에 새 장소/지식/단서가 표시된다.
5. 발견 결과로 지식, 진로 힌트, 특성/성향/스킬, 관계, 퀘스트 중 하나 이상이 변경된다.
6. 같은 발견 지점은 저장/로드 후 중복 보상을 주지 않는다.
7. 플레이어가 하루 종료 지점으로 실제 이동해 하루를 종료한다.
8. 하루 결과 UI에 오늘 발견한 장소/지식/힌트와 변화 결과가 표시된다.
9. 결과 UI 버튼으로 다음 날을 시작한다.
10. 저장 슬롯 UI로 같은 슬롯을 다시 로드해도 발견 상태와 해금 결과가 유지된다.

멀티플레이 확장 고려:
- 발견 상태가 개인 발견인지 공유 월드 발견인지 데이터로 구분한다.
- 개인 지식/진로 힌트는 플레이어별 상태로 유지한다.
- 공유 장소 해금이나 월드 변화는 서버 권한 공유 상태로 확장 가능해야 한다.
- 이번 goal에서 멀티플레이 직접 검증이 범위 밖이면 후속 검증 리스크를 최종 보고에 명시한다.

필수 테스트:
- EXPLORE-EDIT-001: DiscoveryDefinition/LocationDefinition이 Registry 또는 지정 데이터 경로에서 로드된다.
- EXPLORE-EDIT-002: 발견 조건과 결과 전략이 엔티티 ID별 분기 없이 실행된다.
- EXPLORE-EDIT-003: 발견 결과가 지식/진로 힌트/특성/퀘스트 중 하나 이상을 변경한다.
- EXPLORE-EDIT-004: 같은 발견 지점은 저장/로드 후 중복 보상을 주지 않는다.
- EXPLORE-EDIT-005: 개인 발견과 공유 발견을 데이터로 구분할 수 있다.
- EXPLORE-E2E-001: 저장 슬롯 UI로 Town에 진입한다.
- EXPLORE-E2E-002: 학교 수업 없이 실제 이동으로 발견 지점에 접근한다.
- EXPLORE-E2E-003: 실제 Trigger/Prompt/Input 경로로 발견을 발생시킨다.
- EXPLORE-E2E-004: 발견 UI/로그와 도메인 상태가 함께 갱신된다.
- EXPLORE-E2E-005: 하루 결과 UI에 발견 결과가 표시된다.
- EXPLORE-E2E-006: 저장/로드 후 발견 상태가 유지되고 중복 보상이 발생하지 않는다.

완료 조건:
- 학교 수업 없이 Town 탐험만으로 지식/진로 힌트/특성/퀘스트 중 하나 이상이 진행된다.
- 탐험 발견은 실제 이동과 Trigger/Prompt/Input 경로로 검증된다.
- 발견 데이터는 SO와 전략 배열 기반이며 엔티티 ID별 분기가 없다.
- 발견 상태와 보상은 저장/로드 후 유지되고 중복 적용되지 않는다.
- 하루 결과 UI가 오늘 발견한 것과 성장 결과를 보여준다.
- 관련 EditMode/PlayMode 테스트가 통과한다.
- `Scripts/ci/check-no-entity-id-branching.sh`가 통과한다.
- 최종 보고에는 수정 파일, 생성/수정한 SO 에셋, 실행한 테스트, 실제 플레이 검증 흐름, 통과/실패 결과, 멀티플레이 확장 리스크를 포함한다.
```
