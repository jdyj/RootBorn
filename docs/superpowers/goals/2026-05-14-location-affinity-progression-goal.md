# Location Affinity Progression Goal Prompt

아래 프롬프트를 goal 세션에 그대로 붙여 넣고 진행한다.

```text
ROOTBORN Unity 프로젝트에서 "플레이어가 장소를 방문하고 활용한 방식이 장소 숙련도/친밀도로 누적되며, 이 진행도가 새 활동, NPC 반응, 퀘스트, 도감, 진로 힌트, 월드 변화 활용을 해금하는 장소 기반 성장 루프"를 설계/구현/검증해줘.

핵심 의도:
- 플레이어가 어떤 장소를 자주 방문하고 어떻게 활용했는지가 장기 진행도로 남아야 한다.
- 도서관, 공방, 상점, 광장, 골목, 숨은 길 같은 장소가 단순 배경이 아니라 성장 축이 되어야 한다.
- 장소 숙련도/친밀도는 새 활동, NPC 반응, 장소 전용 퀘스트, 숨은 상호작용, 도감, 진로 힌트, 월드 변화 활용으로 이어져야 한다.
- 싱글플레이에서 혼자 모든 장소 성장 루프를 완료할 수 있어야 한다.
- 새 장소와 새 장소 성장 보상은 C# 코드 수정 없이 ScriptableObject 데이터 추가와 Registry 등록만으로 추가 가능해야 한다.

헌법 규칙:
- AGENTS.md와 `.claude/rules/*`를 따른다.
- `Assets/**/*.cs`를 외부 디스크 쓰기로 직접 수정하지 않는다. C# 신규/수정은 반드시 Unity MCP `script-update-or-create` 또는 Unity Editor 안전 경로를 사용한다.
- 모든 게임 엔티티는 100% ScriptableObject 데이터 기반이어야 한다.
- locationId, affinityId, sourceId, rewardId, npcId, activityId, questId별 `if/switch` 분기, enum 기반 엔티티 분기, 장소별 C# 클래스 생성은 금지한다.
- 장소 숙련도 source, 조건, 보상, 레벨/단계, 반복 제한, UI 표시 규칙은 SO 데이터와 전략 배열로 표현한다.
- 도감/진로 힌트/퀘스트/활동/월드 활용/보상은 저장/로드 후 중복 적용되면 안 된다.
- TDD로 진행한다. 먼저 실패하는 테스트를 만들고 실패를 확인한 뒤 구현한다.
- 성능/최적화 동시 설계 원칙을 따른다.
- 기존 dirty 변경을 되돌리지 않는다.

권장 데이터 구조:
- `LocationAffinityDefinition`
  - 장소, 표시명, 설명, 최대 단계, 단계별 필요 진행도, 관련 NPC/활동/퀘스트/도감/진로 후보, UI 표시 정책을 정의한다.
- `LocationAffinitySourceBase[]`
  - 장소 방문, 장소 활동 수행, NPC 대화, 오브젝트 사용, 상점 이용, 포탈 발견, 단서 발견, 퀘스트 완료, 월드 변화 활용을 진행도 source로 정의한다.
- `LocationAffinityConditionBase[]`
  - 장소 발견 여부, 월드 상태, 관심 진로, 시간대, 관계도, 퀘스트 상태, 도감 상태, 아이템 보유를 일반 조건으로 평가한다.
- `LocationAffinityRewardBase[]`
  - 새 활동, NPC 반응, 장소 퀘스트, 도감 항목, 진로 힌트, 상점 품목, 포탈/상호작용, 하루 이벤트 후보를 일반 보상으로 지급한다.
- `LocationAffinityProgress`
  - saveSlot + player identity 기준으로 장소별 진행도, 단계, source 기록, 보상 수령 여부, 마지막 증가 날짜, 오늘 증가 요약을 저장한다.
- `LocationAffinitySummaryModel`
  - 장소 UI, 지도 UI, 하루 결과 UI, 도감/월드 로그 UI에서 공통으로 사용하는 표시 모델이다.

초기 장소 성장 예시:
- 도서관
  - 진행 source: 도서관 방문, 자료실 이용, 사서 대화, 심화 조사, 오래된 기록 단서 발견
  - 단계 보상:
    - 1단계: 자료실 이용 힌트
    - 2단계: 심화 조사 활동
    - 3단계: 사서 해석 대화
    - 4단계: 학습형/탐험형 진로 후보 심화
- 공방
  - 진행 source: 작업대 사용, 수리 연습, 납품 준비, 작업 관리자 대화, 공방 퀘스트 완료
  - 단계 보상:
    - 1단계: 작업대 사용 안내
    - 2단계: 수리 연습 활동
    - 3단계: 납품 준비 활동
    - 4단계: 기술·작업형 견습 퀘스트
- 상점
  - 진행 source: 새 품목 확인, 구매/판매, 배달 도움, 단골 응대, 상점 주인 대화
  - 단계 보상:
    - 1단계: 새 품목 소문
    - 2단계: 배달 도움 활동
    - 3단계: 단골 응대 이벤트
    - 4단계: 관계·서비스형 진로 심화
- 골목/숨은 길
  - 진행 source: 흔적 발견, 숨은 길 포탈 발견, 주변 조사, 지도 기록, 탐험 단서 완료
  - 단계 보상:
    - 1단계: 골목 흔적
    - 2단계: 숨은 길 단서
    - 3단계: 새 장소 발견
    - 4단계: 탐험·정보형 진로 심화

UI 요구:
- 장소 UI에는 현재 장소 숙련도/친밀도 단계, 진행도, 다음 단계 힌트를 표시한다.
- 지도 UI에는 장소별 숙련도/친밀도 배지 또는 진행 상태를 표시한다.
- 하루 결과 UI에는 오늘 증가한 장소 진행도와 새로 열린 장소 보상을 표시한다.
- 도감/월드 로그 UI에는 장소별 발견/활용/성장 기록을 표시한다.
- 장소별 패널은 특정 locationId를 직접 알지 않고 `LocationAffinitySummaryModel`을 렌더링한다.
- 잠긴 단계는 `???`와 일부 힌트만 표시한다.
- 새로 열린 활동/퀘스트/도감/진로 힌트는 명확히 표시하되, 플레이어에게 하나의 정답 경로를 강제하지 않는다.
- Modern UI Style2 공통 패널 규약을 따른다.
- 1920x1080 기준에서 장소명, 단계명, 진행도, 조건, 보상, 버튼 텍스트가 겹치거나 잘리지 않아야 한다.
- UI는 문서 목업만 만들고 끝내면 안 된다. PlayMode에서 실제로 열리고 클릭 가능해야 한다.

확장성 검증:
- 새 장소 성장 루프는 C# 코드 수정 없이 ScriptableObject 데이터 추가와 Registry 등록만으로 추가 가능해야 한다.
- 테스트용 신규 `LocationAffinityDefinition`을 1개 이상 추가하고, 기존 런타임 코드를 수정하지 않은 상태에서 진행도 증가, 단계 상승, 보상 지급, UI 표시, 저장/로드가 동작하는지 검증한다.
- 한 장소는 여러 source로 진행될 수 있어야 한다.
- 같은 source가 장소 숙련도, 퀘스트, 도감, 진로 힌트를 동시에 진행시킬 수 있어야 한다.
- 하나의 장소 단계가 여러 보상/후속 콘텐츠를 열 수 있어야 한다.
- 단계 보상은 중복 지급되지 않아야 한다.
- 반복 source는 하루 제한, 쿨다운, source별 중복 제한을 데이터로 정의할 수 있어야 한다.
- 최종 보고에는 "장소 숙련도 확장성 검증 체크리스트"를 포함하고, SO만으로 추가한 테스트 장소 성장 루프의 실제 플레이 검증 결과를 기록한다.

최우선 실제 플레이 검증 원칙:
- 이 goal은 실제 유저가 플레이하듯 검증하지 않으면 완료로 인정하지 않는다.
- 최소 1개 이상의 PlayMode E2E는 저장 슬롯 UI에서 시작해 실제 키보드 이동, 실제 장소 방문, 실제 NPC/오브젝트/활동/상점/포탈 상호작용, 장소 진행도 증가, 단계 보상 확인, 저장/로드 재진입을 모두 거쳐야 한다.
- 테스트에서 LocationAffinityProgress, WorldStateProgress, QuestLog, Inventory, SaveData 상태를 직접 세팅해서 성공 처리하면 실패다.
- 플레이어 Transform 직접 이동, 내부 메서드 직접 호출, 씬 강제 로드, 저장 데이터 직접 주입, UI 없이 도메인 API 직접 호출로 실제 플레이 경로를 대체하면 완료로 보고하지 않는다.
- 최종 보고 전에 "실제 플레이 방식 상호작용 검증 체크리스트"를 반드시 작성하고, 각 항목을 PASS/FAIL로 표시한다.

실제 플레이 방식 상호작용 검증 체크리스트:
- 저장 슬롯 UI에서 새 게임 또는 기존 슬롯을 실제 UI 경로로 시작했는가?
- 플레이어 이동이 Transform 직접 세팅이 아니라 키보드/입력 시스템 경로로 수행됐는가?
- 장소 방문, NPC 대화, 오브젝트 사용, 활동 수행, 상점 이용, 포탈 발견 중 최소 2개 source가 실제 Prompt/Input/Button 경로로 수행됐는가?
- 수행 결과가 장소 진행도 증가와 UI 표시로 반영됐는가?
- 단계 상승으로 새 활동, NPC 반응, 장소 퀘스트, 도감, 진로 힌트, 월드 변화 활용 중 최소 2개 이상이 열렸는가?
- 하루 결과 UI 또는 장소/지도 UI에서 장소 진행 변화가 공통 summary/card로 표시됐는가?
- 저장 슬롯 UI 재진입 후 같은 슬롯을 로드했을 때 장소 진행도, 단계, 보상 수령 여부가 유지되는가?
- 같은 source나 같은 단계 보상을 반복해도 중복 진행/중복 보상이 발생하지 않는가?
- 테스트용 신규 장소 성장 루프가 SO만으로 추가되어 실제 플레이 경로에서 진행/표시/저장/로드됐는가?
- 체크리스트 항목 중 하나라도 FAIL이면 완료로 보고하지 않고 실패 단계와 남은 작업을 보고했는가?

싱글/멀티 정책:
- 싱글플레이에서 혼자 모든 장소 성장 루프를 완료할 수 있어야 한다.
- 장소 숙련도/친밀도 진행도와 보상 수령 여부는 기본 Personal이다.
- Shared 월드 변화로 열린 장소나 오브젝트는 모든 클라이언트가 볼 수 있지만, 각 플레이어의 장소 숙련도는 별도로 저장한다.
- Client 1이 공방 숙련도를 올렸다고 해서 Client 2의 공방 숙련도가 같이 오르면 안 된다.
- 단, 장소 단계 보상이 Shared 월드 상태를 활성화하는 경우 서버 권한으로 모든 클라이언트에 반영 가능하다.
- 멀티플레이 직접 검증이 이번 범위에 포함되면 실제 클라이언트 2개 이상 또는 Host+Client를 띄워 Shared 장소 변화와 Personal 장소 숙련도 분리를 확인한다.
- 멀티플레이 직접 검증이 범위 밖이면 최종 보고에 후속 NET 테스트 계획을 명시한다.

목표 플레이 흐름:
1. 저장 슬롯 UI로 새 게임 또는 기존 슬롯 로드 후 Town에 진입한다.
2. 플레이어가 실제 이동으로 도서관, 공방, 상점, 광장, 골목 중 하나에 접근한다.
3. 장소 방문, NPC 대화, 오브젝트 사용, 활동 수행, 상점 이용, 포탈 발견 중 하나를 실제 상호작용으로 수행한다.
4. 장소 진행도가 증가하고 장소 UI 또는 HUD/하루 결과 UI에 반영된다.
5. 같은 장소에서 다른 source 하나를 추가로 실제 상호작용으로 수행한다.
6. 장소 숙련도/친밀도 단계가 상승한다.
7. 단계 보상으로 새 활동, NPC 반응, 장소 퀘스트, 도감, 진로 힌트, 월드 변화 활용 중 최소 2개 이상이 열린다.
8. 새로 열린 요소 중 하나를 실제 이동/상호작용으로 확인한다.
9. 하루 결과 UI에서 오늘 증가한 장소 진행도와 열린 보상을 확인한다.
10. 저장 슬롯 UI로 같은 슬롯을 다시 로드한다.
11. 재로드 후 장소 진행도, 단계, 보상 수령 여부가 유지되는지 확인한다.
12. 같은 source나 보상을 반복해 중복 진행/중복 보상이 발생하지 않는지 확인한다.
13. SO만으로 추가한 테스트 장소 성장 루프도 같은 흐름으로 진행/표시/저장/로드한다.

필수 저장 데이터:
- saveSlot
- player identity
- location affinity id
- current affinity value
- current affinity level
- source contribution history
- last source day/time
- reward claimed flags
- unlocked activity ids
- unlocked quest ids
- discovered encyclopedia entry ids
- career hint grant history
- today location affinity summary

필수 EditMode 테스트:
- LOCATION-AFFINITY-EDIT-001: LocationAffinityDefinition/source/condition/reward 전략이 Registry 또는 지정 데이터 경로에서 로드된다.
- LOCATION-AFFINITY-EDIT-002: 새 테스트 장소 성장 루프가 C# 코드 수정 없이 SO 추가와 Registry 등록만으로 로드된다.
- LOCATION-AFFINITY-EDIT-003: 장소 방문/NPC 대화/오브젝트 사용/활동 수행 source가 locationId별 if/switch 없이 진행도를 증가시킨다.
- LOCATION-AFFINITY-EDIT-004: 한 장소가 2개 이상 source로 진행될 수 있다.
- LOCATION-AFFINITY-EDIT-005: 단계 상승 보상이 새 활동/퀘스트/도감/진로 힌트/월드 활용을 전략 배열로 연다.
- LOCATION-AFFINITY-EDIT-006: 같은 단계 보상은 반복 지급되지 않는다.
- LOCATION-AFFINITY-EDIT-007: 저장/로드 후 진행도, 단계, 보상 수령 여부가 복원된다.
- LOCATION-AFFINITY-EDIT-008: 반복 source의 하루 제한/쿨다운/source별 중복 제한이 데이터 기반으로 동작한다.
- LOCATION-AFFINITY-EDIT-009: UI summary 생성이 매 호출 Registry 전체 순회를 요구하지 않는 구조인지 검증한다.

필수 PlayMode E2E 시나리오:
- LOCATION-AFFINITY-E2E-001: 저장 슬롯 UI로 Town에 진입한다.
- LOCATION-AFFINITY-E2E-002: 플레이어가 실제 이동으로 대상 장소에 접근한다.
```
