# Town Help Action Growth Goal Prompt

아래 프롬프트를 goal 세션에 그대로 붙여 넣고 진행한다.

```text
ROOTBORN Unity 프로젝트에서 "학생이 학교 수업을 듣지 않고 Town에서 NPC 도움 행동을 실제 이동/상호작용으로 수행하면 특성·성향·관계·컨디션·진로 힌트 중 하나 이상이 성장하고, 하루 결과 UI와 저장/로드 후 상태에 반영되는 학교 밖 성장 루프"를 설계/구현/검증해줘.

핵심 의도:
- 새 헌법 원칙인 자유 경로 성장 원칙을 실제 플레이 가능한 첫 슬라이스로 증명한다.
- 학교 수업은 중요한 경로 중 하나일 뿐 유일한 정답이 아니다.
- NPC 도움 행동은 마을 생활, 관계, 성향 성장, 진로 힌트를 연결하는 학교 밖 핵심 성장 루트다.

최우선 검증 원칙:
- 이 goal은 실제 유저가 플레이하듯 검증하지 않으면 완료로 인정하지 않는다.
- 최소 1개 이상의 PlayMode E2E는 저장 슬롯 UI, 실제 키보드 이동, NPC 접근, 실제 Prompt/Input/Button 상호작용, 도움 행동 수행, 하루 종료, 결과 UI, 저장/로드 재진입을 모두 거쳐야 한다.
- 테스트에서 Trait/Skill/Relationship/Status/QuestLog/Inventory/StudentLifeProgress를 직접 세팅해 통과시키면 실패다.
- 플레이어 Transform 직접 이동, 내부 메서드 직접 호출, 씬 강제 로드, 저장 데이터 직접 주입으로 실제 플레이 경로를 대체하면 완료로 보고하지 않는다.

절대 규칙:
- AGENTS.md와 `.claude/rules/*`를 따른다.
- `Assets/**/*.cs`는 디스크 직접 쓰기 금지. C# 신규/수정은 반드시 Unity MCP `script-update-or-create` 또는 Unity Editor 안전 경로를 사용한다.
- 모든 게임 엔티티는 100% ScriptableObject 데이터 기반이어야 한다.
- npcId, helpActionId, activityId, questId, traitId, relationshipId, statusId별 `if/switch` 분기, enum 기반 엔티티 분기, 엔티티별 C# 클래스 생성은 금지한다.
- 도움 행동, 보상, 관계 변화, 컨디션 변화, 진로 힌트 해금은 SO 데이터와 전략 배열로 표현한다.
- TDD로 진행한다. 먼저 실패하는 테스트를 만들고 실패를 확인한 뒤 구현한다.
- 기존 dirty 변경 되돌리기 금지.

권장 구조:
- `TownHelpActionDefinition`
  - 도움 행동의 표시명, 설명, 대상 NPC/장소, 필요 조건, 수행 결과 전략 배열을 정의한다.
- `HelpActionRequirementBase[]`
  - 관계, 컨디션, 시간대, 튜토리얼 단계, 퀘스트 상태 같은 조건을 일반 전략으로 평가한다.
- `HelpActionOutcomeBase[]`
  - 특성/성향, 스킬, 관계, 컨디션, 퀘스트 이벤트, 진로 힌트, 인벤토리 보상을 일반 전략으로 적용한다.
- `TownHelpActionInteractor`
  - 월드 오브젝트 또는 NPC에 붙어 실제 플레이 상호작용 경로를 제공한다.
- `StudentDaySummary` 또는 하루 결과 요약 구조 확장
  - 오늘 도움 행동과 성장 결과를 결과 UI에 표시한다.

목표 플레이 흐름:
1. 저장 슬롯 UI로 새 게임 또는 기존 슬롯을 로드해 Town에 진입한다.
2. 플레이어가 학교 수업을 수행하지 않은 상태에서 NPC 도움 행동 지점을 찾는다.
3. 플레이어가 실제 이동 입력으로 NPC 또는 도움 행동 오브젝트에 접근한다.
4. 실제 상호작용 입력과 UI 버튼으로 도움 행동을 수락하거나 수행한다.
5. 도움 행동 결과로 특성·성향·관계·컨디션·진로 힌트·퀘스트 진행 중 하나 이상이 변경된다.
6. 변경 결과가 HUD, QuestLog, 관계/컨디션 표시 또는 즉시 피드백 UI 중 하나 이상에 보인다.
7. 플레이어가 실제 이동으로 하루 종료 지점에 접근한다.
8. 실제 상호작용 입력으로 하루를 종료한다.
9. 하루 결과 UI에 오늘 수행한 도움 행동과 성장/관계/컨디션 변화가 표시된다.
10. 결과 UI 버튼으로 다음 날을 시작한다.
11. 저장 슬롯 UI로 같은 슬롯을 다시 로드해도 도움 행동 결과와 성장 상태가 유지된다.
12. 같은 도움 행동 또는 같은 하루 결과를 재호출해도 중복 보상/중복 성장/중복 관계 변화가 발생하지 않는다.

멀티플레이 확장 고려:
- 도움 행동 정의와 결과 전략은 서버 권한 요청/확정 구조로 감쌀 수 있어야 한다.
- 개인 성장, 개인 관계, 개인 컨디션, 개인 퀘스트 진행은 플레이어별 상태로 분리한다.
- 공유 월드 도움 행동 오브젝트의 소모/재사용 여부는 데이터로 정의한다.
- 이번 goal에서 멀티플레이 직접 검증이 범위 밖이면 최종 보고에 후속 검증 리스크를 명시한다.

필수 테스트:
- HELP-EDIT-001: 도움 행동 정의가 Registry 또는 지정 데이터 경로에서 로드된다.
- HELP-EDIT-002: 도움 행동 요구 조건과 결과 전략이 엔티티 ID별 분기 없이 실행된다.
- HELP-EDIT-003: 도움 행동 결과가 특성/관계/컨디션/진로 힌트 중 하나 이상을 일반 전략으로 변경한다.
- HELP-EDIT-004: 같은 도움 행동 결과를 같은 request id 또는 같은 하루 상태로 재적용해도 중복 적용되지 않는다.
- HELP-E2E-001: 저장 슬롯 UI로 Town에 진입한다.
- HELP-E2E-002: 학교 수업을 수행하지 않고 실제 이동으로 NPC 도움 행동 지점에 접근한다.
- HELP-E2E-003: 실제 상호작용 입력/UI 버튼으로 도움 행동을 수행한다.
- HELP-E2E-004: 학교 밖 도움 행동만으로 성장/관계/컨디션/진로 힌트 중 하나 이상이 바뀐다.
- HELP-E2E-005: 하루 종료 결과 UI에 도움 행동과 변화 결과가 표시된다.
- HELP-E2E-006: 저장/로드 후 결과가 유지되고 중복 적용되지 않는다.

완료 조건:
- 학교 수업 없이 Town 도움 행동만으로 핵심 성장 또는 관계/컨디션/진로 힌트 진행이 가능하다.
- 실제 플레이 E2E가 학교 밖 경로를 증명한다.
- 도움 행동은 SO 데이터와 전략 배열 기반이며 엔티티 ID별 분기가 없다.
- 하루 결과 UI와 저장/로드가 도움 행동 결과를 반영한다.
- 관련 EditMode/PlayMode 테스트가 통과한다.
- `Scripts/ci/check-no-entity-id-branching.sh`가 통과한다.
- 최종 보고에는 수정 파일, 생성/수정한 SO 에셋, 실행한 테스트, 실제 플레이 검증 흐름, 통과/실패 결과, 멀티플레이 확장 리스크를 포함한다.
```
